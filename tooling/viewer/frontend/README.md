# Viewer frontend

This standalone React application uses public MIT shadcn/ui and ReUI components, installed with shadcn 4.22.1 (`base-nova`). No premium block is included. Full runtime and copied-component license notices live in `THIRD_PARTY_NOTICES.md` and are preserved as a comment banner in the shipped JavaScript. `cn` is the real MIT shadcn-ui class-merging package used by the generated component imports.

Use Node 24 or newer and pnpm 12.8.1. Run `pnpm install --frozen-lockfile`, `pnpm check`, `pnpm lint`, `pnpm test`, `pnpm build`, and `pnpm verify:dist` here. The ordinary Go build consumes checked-in output without Node. The local package retains a seven-day release-age policy, with exact exceptions for reviewed React 19.3.1, react-dom 19.3.1 and cn 0.5.0. Their registry metadata identifies the upstream React and shadcn-ui repositories and MIT license, with no installation lifecycle scripts. Build transitive dependencies use mature rolldown 1.2.13 and postcss 8.5.30; lucide-react uses mature 1.55.0. The installer CLI is not a runtime or build dependency.

`pnpm dev` uses the real same-origin viewer API by default and serves the unchanged shared renderer from `../static/`. The development server does not supply the Go API, so without it the client shows an explicit access or connection error. Add `?preview` for the development-only generated composition; `?preview&state=loading`, `?preview&state=empty` or `?preview&state=error` selects its states. The fixture is eliminated by Vite's production `DEV` branch. Production has no sample data and always uses the real API. The shell uses browser-language English/Spanish strings and retains the dark product theme.

The production client exchanges the opening code before consuming the library, polls the index, and supports selection, archiving and restoring, keeping, deleting sessions and reconnection. The sidebar groups copies by exact project, host and declared session ID, with visible-session counts and compact title, ticket summary, segment count and date rows. Opening a session from the sidebar shows its complete header, even after a continuation was selected. Explicit segment links and ticket search jump to the requested segment; refreshing the tab restores its selected segment. Tickets are metadata rather than another navigation level; their segments are stacked chronologically inside the selected session with separators and ticket search jumps. Archive filtering applies to logical sessions: all members share visibility, including new continuations. The local session name, when set, overrides the derived title in the sidebar, fixed toolbar and search; individual walkthrough titles remain unchanged. A project initially opens only when it contains work explicitly in progress, and manual expansion overrides that default. Sidebar visibility, project expansion, archive filter and selection survive refresh through sessionStorage in the same tab and origin. The renderer remains shared with offline pages. A development composition does not verify production authentication or CSP; check the compiled bundle served by Go.

The sidebar brand header shows a route icon. The fixed session toolbar owns rename, archive/restore, keep/unkeep and confirmed deletion for the entire logical session. The document canvas alone scrolls. Each walkthrough retains its informational work-status indicator but no duplicate management controls. Brief shell feedback offers Undo for archive even after selection changes. Rename uses a prefilled Dialog; deletion uses AlertDialog and counts all stored members, including archived or excluded copies. The session header collects explicit delivery links from accessible visible segments, deduplicated by URL, with two direct links and access to the rest; each document retains its own links. Missing metadata is distinct from a failed or pending document read. Delivery URLs use the manifest ASCII-host HTTPS contract and labels remain text; the captured candidate is separate. Simultaneous documents scope IDs, ARIA references, media and print listeners to their own roots and dispose handlers when unmounted. Status consumes explicit `session_status` from the API: `in_progress`, `closed` or `unknown`; the viewer does not edit it. Only individual walkthroughs show work-state indicators; a session is not labeled as a closed conversation. An in-progress member still opens its project by default. Work closure is distinct from approval. Historical manifests without `session.status` remain `unknown`; source classification and work status are independent. The icon-only archive toggle beside Projects has a tooltip and accessible label; archived sessions are hidden by default. Session preferences are persisted separately from copy resources, independently of retention and manifest status, and never edit source files. New deliveries inherit archive and keep preferences. Deletion removes current copies with tombstones; new or modified content can return. See the [manifest contract](../../../content/skills/flow-walkthrough/references/walkthrough-manifest.md) and [canonical close procedure](../../../content/skills/flow-close/SKILL.md#close-the-current-walkthrough) for production and confirmation of closure.

Session writes require `X-Hive-Action-Scope: session`; older tabs receive `409 reload_required` without mutation and must reload. `PUT /api/sessions/<member-key>/title` accepts a JSON title (trimmed, at most 200 Unicode code points; empty resets). The index adds optional `session_title`; reads and resource capabilities remain per copy. `partial_delete` errors expose `deleted`, `remaining` and `cleanup_pending`; clients refresh authoritative state and distinguish retryable surviving copies from automatic cleanup with no members. Index errors tagged `delete_cleanup_pending` remain visible until background recovery succeeds; checking recovery only reads the index.

Tailwind preflight is deliberately omitted so it cannot reset the shared document. Shell resets are scoped; the shared renderer and its stylesheet remain external assets. Base UI 1.9.0 `CSPProvider disableStyleElements` is corroborated against its versioned official documentation via Context7. Scrollbar fallback styles and root isolation are external CSS. No theme provider injects scripts.

## Bundle contract (version 1)

`../static/app/bundle-manifest.json` is generated after Vite succeeds. It is JSON formatted with two spaces and a trailing newline. Object fields are `version` (1), `sourceDigest` (lowercase SHA-256 hex), `entrypoint` (`index.html`) and `files` (sorted by relative path). Each file record contains `path`, `sha256` (lowercase SHA-256 of exact file bytes) and `mime`. MIME values are exactly `text/html; charset=utf-8`, `text/javascript; charset=utf-8`, and `text/css; charset=utf-8` for `.html`, `.js`, and `.css`. No other extension is currently emitted or accepted. The manifest itself is not a public asset.

The HTML is served at `/`. Other declared output paths are served at `/assets/app/<path>`. The external renderer remains at `/assets/walkthrough.mjs` and `/assets/walkthrough.css`; it is not copied into this output. The dedicated output directory is the only directory cleaned by build. Source maps, inlined assets and external CDN resources are disabled.

The source digest enumerates all regular frontend files recursively, sorts their slash-separated relative paths by code point, and hashes the UTF-8 concatenation of each `path + NUL + sha256(fileBytes) + LF`. Exclude any path component named `node_modules`, `.git`, `coverage`, `playwright-report`, `test-results` or `.DS_Store`, any component starting `.env`, and any component ending `.local`. Reject symbolic links. The output is outside the source root. Thus package metadata, lockfile, configs, copied components, tests and scripts all participate. Only public development configuration belongs here; credentials do not. Go can implement the same algorithm without Node.

Verification is read-only. It rejects stale source digests, altered asset hashes, invalid MIME/path metadata, missing files and undeclared extra output files. This is freshness checking, not a signature or a security guarantee. Regenerate after any source change, including this README, and commit the generated output with that change. Rebuilds with the frozen lockfile must produce identical output. `go test ./tooling/viewer` from the repository root checks the source digest without Node; ordinary Go builds and package builds consume the checked-in bundle.
