# Portable harness engineering: research and design implications

Research checked 2026-09-20 (America/Mexico_City). This is a source-backed design basis, not a product specification or proof that a Hive candidate improves results. The five-host rebuild scope is Claude Code, Codex, Grok Build, Pi, and OpenCode V2. A same-day local inventory reported Claude Code 2.1.278, Codex 0.155.1, Grok 1.0.34 (`3736acbc8658`, stable), Pi 0.86.0, and OpenCode 2.0.9; documentation URLs below are rolling pages unless versioned, not proof that the installed builds behave as documented. The earlier pilot and research snapshots sometimes name only four hosts; this document reflects the later five-host objective.

## Finding

The evidence favors a small, always-available map of essential guidance, with task procedures and situational detail loaded only when relevant. It does not support reproducing a separate prompt system for each host, assuming a skill is always selected, or adding hooks and adapters merely to make the architecture look uniform.

Hive's cross-cutting workspace conventions are an exception to activity routing: artifact placement needs to work even when no activity skill is selected. Keep the few placement rules in the project-wide instruction that all target hosts read, with `CLAUDE.md` importing `AGENTS.md` where Claude requires that bridge. Activity skills should carry their own indispensable procedure and link directly to a reference only when its stated condition applies. Host-specific mechanisms belong in small adapters only after documentation and observed runs establish a concrete gap.

Pi warns that models may skip skills. Presence, selection, reference reading, and compliance are separate; measure them separately.

## What external results do and do not establish

Vercel reported its Next.js API skill was not selected in 56% of cases. In that fixture, success was 53% baseline, 53% with a default-available skill, 79% when instructed, and 100% with an `AGENTS.md` docs index ([evaluation](https://vercel.com/blog/agents-md-outperforms-skills-in-our-agent-evals)). This shows delivery affected that task set, not that AGENTS universally beats skills.

Uber's 2026 software-factory article labels costs 34% below peak per 1,000 requests and 52% below peak per session while user count grew 7× and requests 9.4×, with one model held fixed. “Below peak” is not an identical before/after workload comparison. These are internal, concurrent system-level results, not an isolated experiment that attributes savings to a single design choice; a fixed model does not fix task mix, user behavior, or simultaneous optimizations. A figure also reports the same model costing $2.22 versus $0.94 per code review across two harnesses, with nearby but unequal F1 scores: an illustration that host behavior matters, not a controlled comparison of Hive design. Its cost decomposition—users × sessions/user × turns/session × requests/turn × tokens/request × price/token—helps diagnose cost; it does not make raw token counts a proxy for successful work. The article's 24-million-node knowledge-graph example is illustrative, not a requirement to build a graph for Hive. Its MCP example describes Uber's eager schema integration, not an MCP protocol requirement: the [2025-06-18 MCP tools specification](https://modelcontextprotocol.org/specification/2025-06-18/server/tools) supports listing and calling tools but leaves discovery/loading strategy to the client.

Other practitioner material is useful as experience rather than controlled evidence. Birgitta Böckeler's article, published by Martin Fowler, distinguishes feedforward guidance from feedback sensors: instructions alone cannot show whether they worked, while feedback alone does not prevent repeated errors ([“Harness engineering”](https://martinfowler.com/articles/harness-engineering.html)). Mitchell Hashimoto describes high-leverage bounded work and verification tools from his own adoption journey ([article](https://mitchellh.com/writing/my-ai-adoption-journey)). A bundled Hyde thread could not be verified from its primary URL during the source review; its attribution/date are treated as supplied context, not independent evidence. Two Hyde texts in the provided packet reconstruct and synthesize that same thread, so they are one source chain, not independent confirmation.

## Prompt caching is not instruction delivery

Caching changes the cost and latency of reprocessing a matching prefix; it does not cause an unloaded skill or unread reference to enter context. Cache behavior depends on model, provider, request bucket, identical prefix, and idle time. OpenAI's current API docs state GPT-5.6+ has a 30-minute minimum cache lifetime after reuse; GPT-5.5/5.5 Pro typically retain entries around 30 minutes and can support up to 24 hours; earlier models vary, with `in_memory` typically 5–10 minutes inactive (up to one hour) or an optional 24-hour retention path where supported ([OpenAI prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching)). This is API documentation, not a measured Codex CLI billing profile. Claude Code currently uses a one-hour main-conversation TTL for included subscription usage, while API/usage-credit requests default to five minutes; auxiliary request buckets are generally five minutes, subject to version and configuration ([Claude Code prompt caching](https://code.claude.com/docs/en/prompt-caching)). Do not claim that a 30-minute or one-hour cache makes always-loaded rules free or that all five hosts share these semantics.

## Hive pilot: current evidence is insufficient for a quality claim

The retained pilot record (historical evidence omitted from public history) reports successful deployment checks across five hosts, but those checks establish delivery, not improved behavior. Across isolated screening and later native cases:

- The isolated Codex research and save cells had correct skill/reference reads and placement; exploratory model grading was 10/10 for both arms on the same fixture, and the requested model identity was unresolved.
- Native Claude research did not load `flow-research`. The earlier corrected isolated standalone-save pair read references before the effective write; the later native save required a rerun after a permission/hook block. These are different checks, not a native baseline/candidate pair or a reliability estimate.
- Pi research missed a required search reference; its save read a sibling Claude finding, contaminating independent attribution.
- Grok research reused Codex output from shared Engram memory; its save read sibling findings and memory. Its candidate's one-point exploratory score difference is not causal evidence.
- OpenCode V2's save cell was independently verified, while research missed a needed reference and made arithmetic/causal errors.

The eight-answer grading was an exploratory model-agent review, not the rubric's required human review. No human validation occurred; there is no demonstrated quality improvement. In an earlier isolated Codex checkpoint, returned research instructions were 47,289 characters at baseline and 40,490 for the candidate, while standalone-save reads rose from 38,290 to 67,516. These are two task traces, not a general burden measure. Reported core reductions of 124 Claude and 6 Codex/OpenCode “tokens” came from bytes divided by four, not a tokenizer. Neither set of figures proves lower maintenance or cost. Real compaction behavior was not reached in the earlier screening; do not infer cross-host persistence.

## Recommendations (inference)

1. Keep a small `AGENTS.md` as the reliable common map for scope, evidence, preservation, and automatic workspace placement. Keep `CLAUDE.md` as a minimal import only. Do not require a workflow skill to be selected before an agent knows where its artifact belongs.
2. Put the indispensable procedure in one activity skill. Link its conditional references directly from that skill, and name the situation that requires each read. Avoid index→router→reference chains and duplicate copies of the same rule in skills, hooks, and agent packs.
3. Use host-native authentication, model loops, tools, permissions, and histories. Add an adapter, hook, or deterministic check only for a measured failure the host exposes no simpler native way to prevent. Do not build a universal proxy or framework to normalize undocumented differences.
4. Preserve the practical design lesson from “ya de paso” as scope control, not a blank check: security-critical or directly related defects can be surfaced with evidence; unrelated debt stays separate. A critical finding does not authorize production changes, and relatedness does not approve new contracts, data boundaries, or scope.
5. Treat skills and references as hypotheses to evaluate, not as self-validating configuration. An idea such as dynamic routing, a universal rule budget, automatic memory extraction, or extra subagents needs a concrete failure and a measured benefit before it becomes permanent.

## Minimum useful evaluation

Use a few discriminating cases drawn from observed failures: correct automatic artifact placement without invoking an activity skill; research that must read one conditional source before making a claim; a question that must not be misread as implementation permission; and a bounded “related issue” that must not expand into unrelated work. Keep baseline and candidate fixtures independent: fresh disposable project and memory IDs, no sibling-output reads, same CLI version, model, task, and permissions within each comparison.

Record, separately: (1) whether the host discovered/selected the expected guidance; (2) whether it read required sources before the decision/write; (3) task outcome against a frozen, observable rubric; (4) human intervention, time, and input/cache measurements available from that host. Require terminal completion evidence. Resolve and record the actual model; requested model metadata alone is insufficient. Blind human grading is separate from the model output and rubric compliance. Start with paired examples, expand only when a defined reliability question requires repeats, and agree the advancement criterion before running. No arbitrary global token limit is warranted by this research.
