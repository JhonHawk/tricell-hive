# rule-delivery

**A gate, not an advisory** — it denies a write and says what to read.

Claude Code's `paths:` loads a path-scoped rule when a matching file is READ, so creating the
first file of a kind never loads it, and every read-only agent that opens a `.ts` pays for a
rule it will never apply (54% of the injections measured on 2026-09-18). This hook replaces
that mechanism with the only primitive every harness enforces: a denial carrying a short reason.

```
PreToolUse   Write src/a.ts   ->  denied: "Held: read typescript-standards.md in
                                           ~/.claude/…/references/ first, then
                                           re-issue this call."
PostToolUse  Read  …/typescript-standards.md
                                ->  observed; the rule is now KNOWN for this session+agent
PreToolUse   Write src/a.ts   ->  allowed
```

**The directory is named once, the basenames after it.** Six absolute paths do not
fit Grok's ~264-character clip, which used to cost three to five sequential denial
rounds for one `.tsx`; the compact form delivers the same six in 229 characters and
one round. Same shape on every harness.

**Two events, one job each.** `PreToolUse` gates and records nothing. `PostToolUse` observes and
denies nothing — it fires only for calls that actually RAN, so a read the user refused (the rule
files live outside the project, and Claude Code may ask) is never recorded as a read.

A rule becomes known **only** by observing that agent read its text. A denial does not mark it
known, and no rule text ever travels in the hook's output. There is no chunking, no transcript
reading and no notion of a turn: the parallel writes of one assistant message are simply denied
too, each with the same reason, which is what makes them safe without any of that machinery.

## What it gates

The manifest (`harness/rule-manifest.json`, generated by `harness/build.py` and deployed beside
the hook) decides. A rule is gateable when ALL hold:

- `globs` is a non-empty list of strings and the rule is not `always_on`;
- its `source` is under `global/rules-situational/` — a rule under `global/rules/` is
  always-on everywhere, and gating it would ask for a read of what the session already has;
- the manifest names a `references` path for the running harness AND that path is a readable
  regular file (a directory, an unreadable file or a missing one is skipped, never gated on);
- its globs are usable: a glob expanding past 256 brace alternatives makes the rule
  undeliverable rather than costing every call the expansion.

With today's manifest that is the 19 rules carrying `globs:` under
`global/rules-situational/`.

**Two frameworks can claim the same file convention** — `*.service.ts`, `*.module.ts`,
`*.guard.ts` are Angular's and NestJS's alike — and an agent carrying one framework's
pack would otherwise be held on the other's rule forever. A rule declares
`exclusive-with: <rule names>` in its frontmatter; the manifest carries it as
`exclusive_with`, and the hook skips that rule for any agent whose packs name one of
them. `harness/build.py` refuses a name that is not a rule. An UNPACKED caller (main
thread, a generic agent) still receives both — that over-hold is exactly what native
path-scoping used to load. **The exclusion is whole-rule, not per glob:** an agent
carrying `nestjs-patterns` is never held for `angular-patterns`, including on
`*.component.html` and `angular.json` (and the reverse). In a front+back monorepo that
is a routing misfire the gate will not catch — the cost of settling the question once,
off the pack the agent already carries, instead of guessing per file.

## What a glob is matched against

**The absolute realpath of the target, always.** It already contains the repo's own
folder name, so a glob anchored on it — `**/*-specs/**`, `**/*-infra/**` — fires with
no derivation at all.

Deriving a project-relative path instead (`basename(cwd)/…`, then `basename(root)/…`)
produced three separate false skips before this was simplified: a `cd` into a
subdirectory, a `/tmp` vs `/private/tmp` spelling, and a Codex payload with an empty
`cwd`. Each changed what the "project" was believed to be. There is nothing left here
to get wrong.

`realpath` normalizes both sides of every comparison, so the two spellings of one
directory on macOS resolve to the same place.

**`cwd` is used for exactly one thing: making a RELATIVE target absolute** — a Codex
`apply_patch` path, a Grok relative `file_path`. The base is the first non-empty of the
payload's `cwd`, `workspaceRoot`/`workspace_root`, `workspace_roots[0]` (the shape Codex
sends when `cwd` is empty — `bash-policy.sh` reads the same one), then the hook's own
directory. A `cwd` pointing at a subdirectory is harmless here: a relative path is
relative to it by definition. If even the last resort fails — `getcwd()` raises once the
process's own directory has been deleted — the path stays relative and is matched as it
stands, never short-circuited to allowed.

Two fixed exemptions on the absolute path are never gated:

- **harness-owned roots** — `~/.claude`, `~/.codex`, `~/.grok`, `~/.agents`, `~/.pi`,
  `~/.config/opencode`. Memory files, plans and agent configs are not project code,
  and their paths carry the project slug, which makes them match by accident.
- **OS temp roots** — `$TMPDIR`, `/tmp`, `/private/tmp`, `/var/folders`,
  `/private/var/folders`. Session scratchpads are not project code either.

**Generated trees are never gated:** a DIRECTORY component named `node_modules`,
`dist`, `.next`, `.turbo`, `.venv`, `__pycache__` or `coverage`. The file's own basename
does not count — a file called `dist` is source. Three names were deliberately left
out: `build`, `vendor` and `target` are real hand-written source directories somewhere
(`harness/build/` in this very repo), and exempting them skipped the rules for source.

Both exemptions are matched on the absolute path, ancestors included. See
*Known limits* for what that costs.

Globs match **by path segment**, never by substring: `**/_support/**` does not fire on
`src/customer_support/…`, `Dockerfile*` does not fire on `NotADockerfile.md`. `**` spans
directories, `*` stays inside one segment, `{a,b}` expands, and a glob with no `/` matches the
basename. `[` and `]` are **literal**: no rule uses a character class, and `app/[locale]/**`
means the directory it looks like. The matcher is a two-pointer wildcard match rather than a
regex — `**a**a**a**a**a**b` makes a backtracking engine run for minutes.

## Who is gated

| Caller | Gated on |
|---|---|
| Main thread, or any agent that can write | its first **write** of a file a rule scopes |
| Agent listed in the manifest's `agents` map | nothing, for the rules its packs already inline |
| Agent in `read_only_agents` | its first **read** of a file a `readers` rule scopes — never a write |

A read of a rule's own text is never denied, whatever the globs say — otherwise a `**/*.md`
`readers` rule would deny the exact read it demands. Agent identity comes from `agent_type`
(recorded inside subagents on Claude Code 2.1.277 and Codex 0.155.0); on Grok it is
`subagentType` — camelCase only, present on every event inside a child and absent on the main
thread (recorded on 1.0.34; the user guide bundled with the binary documents it), while a packed
agent run as the PRIMARY Grok session (`grok --agent <name>`) carries no identity at all and is
gated like the main thread; on PI it comes from `PI_HIVE_AGENT`, which the reviewed `pi-subagents`
patch exports from the child launch (`childProcessEnv`) and the Hive extension reads once as it
loads, so a later launch in the same runner process cannot relabel an in-flight call; an unpatched
or un-deployed `pi-subagents` leaves it unset, and the caller is gated as the main thread).
With no agent identity the caller is treated as the main thread,
whose only consequence is gating a rule an agent may already carry. State is keyed by
`agent_id` when there is one and by `agent_type` otherwise, never collapsed into the main
thread's.

## Per harness

Each hook command line exports `HIVE_HARNESS`, which picks the reference root and the reason
budget. Grok is the exception by construction: it reads the **Claude** settings block, so it
inherits `HIVE_HARNESS=claude` and is recognized by its own camelCase payload keys instead.

| Harness | Gated (PreToolUse) | Observed (PostToolUse) | Reason budget | State cleared |
|---|---|---|---|---|
| Claude Code 2.1.277 | `Write`, `Edit`, `MultiEdit`, `NotebookEdit` (`notebook_path`), plus a patch written through `Bash` | `Read`; a reader command in `Bash` | 8,000 (24 KB verified) | `SessionStart` `compact\|clear`, wired |
| Grok 1.0.34 | `write`, `search_replace`, `edit_file` — relative paths resolved against `cwd`/`workspaceRoot` | `read_file`; `run_terminal_command`/`run_terminal_cmd` | 260 (~264 visible chars, clipped) | inherits Claude's `SessionStart` block through the compat layer — **unverified** |
| Codex 0.155.0 | `apply_patch` (`Add File:`, `Update File:`, `Move to:`; `Delete File:` authors nothing), plus a patch written through `Bash` | `Bash` — Codex has no read tool, so this is its ONLY release | 8,000 | **not wired: no Codex compaction event is documented or verified**, so state survives a compaction there |
| PI | `write`, `edit` — blocked with the hook's own reason, in CHILD sessions too (those are the ones that write code) | `read`, `bash`, on `tool_result` | 260 (PI clipping unmeasured — the conservative budget) | no (the bridge has no compaction channel for this hook) |

Notes that are not stylistic:

- **The reason names as many rules as the budget allows**, least-counted first, grouped by
  directory. A path that cannot be named **whole** is never clipped: that rule is simply not
  gated on that harness — on Grok a ~420-char reference is delivered by other means, while
  Claude names it in full.
- **Codex's reason carries the command itself** — `… first — run: cat <abs paths> — then
  re-issue this call.` Codex has no read tool, so a shell reader is its only way out of the
  gate; the other harnesses get the plain form.
- **A terminal call is denied only when it carries a patch** (`*** Add File:` and friends): those
  headers author files exactly like `apply_patch`. Any other shell call is observation-only.
- **A shell command is parsed, not searched — once per call, never once per rule.** It is split
  on newlines (honouring quotes: a multi-line command is a sequence, not one line), unwrapped
  (`bash -lc '…'`, argv arrays as Codex sends them, leading `VAR=value` / `sudo` / `env` /
  `command`), tokenized with `shlex`, and split into simple commands on `;`, `&&`, `||`, `|`. A
  rule counts as read when a simple command's argv[0] basename is a reader (`cat`, `head`,
  `tail`, `sed`, `less`, `bat`, `nl`), has no **stdout** redirection, is not `sed -i`, is not
  `head`/`tail` with a zero count or `tail -f`, one of its ARGUMENT tokens resolves to the rule
  file, and every later stage of its pipeline is also a reader.
  **The exact forms observed**, each verified against the real manifest: `cat <abs path>`;
  `cat ~/…` and `cat "$HOME/…"`; `cat a.md b.md` (several files, one command); `sed -n '1,200p' a.md
  && sed -n '1,200p' b.md`; `bash -lc 'cat …'` and an argv array as Codex sends it; a leading
  `VAR=v` / `sudo` / `env` / `command`; `cd <dir> && cat a.md b.md`, where `cd` moves the base the
  later stages resolve against — **not** the payload's cwd; `cat <dir>/*.md` and
  `cat <dir>/{a,b}.md`, expanded by looking at the filesystem (never executed, and a pattern
  matching no existing file names none). **Redirecting stderr changes nothing** —
  `cat rule.md 2>/dev/null` and `cat rule.md 2>&1 | head -200` both release it.
  **Not observations, by design:** a loop (`for f in …; do cat "$f"; done` — loop variables are
  not tracked, which is why the Codex reason names a command that IS observed),
  `grep`/`rg`/`awk`, `cat rule.md | tee x`, `cat < rule.md`, `$(cat rule.md)`, `(cat rule.md)`,
  `rm rule.md`, `cat rule.md.bak`, `cat rule.md > copy`, `tail -f app.log # see rule.md`.
  Anything `shlex` cannot parse is not an observation, and neither is a command over 64 KB — it
  is not parsed at all (measured: 38 rules against a 1 MB command cost 24 ms, both events).
- **A shell call is a patch write only when it opens one:** the headers count when they start a
  line AND the command contains `*** Begin Patch`, so `git commit -m '…*** Update File: …'`
  authors nothing.
- **A read is matched by identity, not by name:** `~` expansion, then `realpath`, then
  `samefile` — so a symlink, `..` segments and (on a case-insensitive volume) a different case
  all resolve to the same file, while a same-named file elsewhere does not. A `Read` with
  `offset` past the first line showed nothing of the rule's head and does not count.
- **A call that visibly failed is not an observation:** a tool response carrying `is_error`,
  `interrupted`, or a non-zero `exit_code` showed the model nothing. Any other response shape
  (or none) is observed as usual — the model is cooperative, and this is not a lie detector.

## Failure mode

It sits in front of every file write in four harnesses, so the failure mode matters more than
the features:

- **Never wedge.** A denial is issued only when the fact of having issued it was recorded first;
  if the state cannot be written (read-only `$TMPDIR`, a 555 directory, a full disk) the call is
  **allowed**. Without a `session_id` the hook keeps no state and never denies. And the release
  valve below bounds the rest.
- **The bound is time, not calls: three counted denials per rule, at least 5 seconds apart.** A
  denial counts only if that rule was NAMED in its reason and the previous counted denial of the
  same rule is older than the window, so a burst of parallel writes counts once and a model
  retrying in a tight loop cannot spend the valve. A model that never reads anything is
  therefore held for ~10 seconds per rule and then let through; a model that reads is released
  at once. The window is `DENIAL_WINDOW` (`HIVE_RULE_DELIVERY_WINDOW` overrides it; the tests
  set it to 0 rather than sleeping).
- **A denial is counted when this hook issues it, not when the call dies.** Another hook on the
  same event can deny the same call for its own reasons; this one has already recorded its
  denial, which makes the valve slightly more generous, never less.
- **Releasing one rule never releases the call.** When every rule NAMED in a denial hits its
  valve, the reason comes back empty — and the rules the budget deferred to a later round are
  still unread. The gate then takes the next group and keeps holding for those, instead of
  letting the write through on somebody else's release.
- **The bound scales with the number of budget-deferred GROUPS, and with the model's own
  re-issue interval** — it is not a fixed ten seconds. Each group costs 2 counted denials, and
  a counted denial needs the previous one to have aged past the window, so the release lands at
  about `2G × max(window, re-issue interval)`. Measured on the real manifest with a fake clock,
  Grok budget:

  | re-issue interval | 1 group (6-rule `.tsx`) | 2 groups (10-rule `_support/spec/a.tsx`) |
  |---|---|---|
  | ≤ 1 s (tight retry loop) | 9–10 s, 10–46 denials | 9–11 s, 11–47 denials |
  | 5 s | 10 s, 2 denials | 20 s, 4 denials |
  | 6 s | 12 s, 2 denials | 24 s, 4 denials |
  | 10 s | 20 s, 2 denials | 40 s, 4 denials |
  | 30 s | 60 s, 2 denials | 120 s, 4 denials |

  Ordering the deferred groups by DIRECTORY (the reason names a directory once, so a group that
  straddles two pays for both) cut the real worst case from three groups to two: a compliant
  agent now pays **1** denial round for the `.tsx` and **2** for `_support/spec/a.tsx`.
- **Fail open.** `HIVE_RULE_DELIVERY=off|0|false|no` (case-insensitive) exits before reading
  stdin. Any exception exits 0 with an empty stdout — no traceback reaches the harness. A
  missing or corrupt manifest, a malformed payload, `globs` that is not a list of strings, a
  path carrying a NUL: all resolve to "allow", never to "block".
- `HIVE_RULE_MANIFEST` overrides the manifest path (the tests and the in-vivo gate use it).

## State

One `0700` directory per `(session_id, agent)` under `$TMPDIR/hive-rule-delivery/`, holding
empty marker files created with `O_CREAT|O_EXCL`. Two kinds, both named by a **hash** of what
they key so no rule name can be a prefix of another (`communication-format` and
`communication-format-mechanics` both exist):

- `k<hash(rule)>` — this agent has read that rule's text.
- `d<hash(rule)>-<1..3>` — one counted denial. The ordinal is *claimed*, not counted, and
  ordinal k is claimable only once ordinal k-1 has aged past the window. Claiming ordinal 3
  releases the rule and lets that call through.

Inside a Codex subagent `session_id` is the PARENT's — only the agent separates them, which is
why the key is always the pair. `SessionStart` with `source` = `compact` or `clear` drops that
session's directories (main thread and subagents alike), so the gate re-arms after a compaction;
directories older than 7 days are pruned when a new one is created.

## Known limits

**The gate points a cooperative model at a file it should read. It is not a security
boundary, and none of the following is treated as a defect** — a model that wants out
can also simply wait for the valve.

- **A project that lives under a temp root is ungated**, entirely: probe sandboxes,
  scratch checkouts, anything under `$TMPDIR`, `/tmp` or `/var/folders`. The exemption
  cannot tell a scratchpad note from a real checkout that happens to live there, and
  gating every temp file is the worse of the two errors.
- **A project inside a `node_modules`/`dist`/`.next`/`.turbo`/`.venv`/`__pycache__`/
  `coverage` directory is ungated**, because ancestors count. Accepted: none of those
  names is a plausible ancestor of a real project, and a checkout inside one is
  vendored or generated by definition.
- **An ancestor directory can gate a file it has no business gating** — the flip side
  of matching absolute paths. A false hold costs one read; a false skip costs the rule.

- **Shell operators are not evaluated, only split on.** `false && cat rule.md`,
  `cd dir || cat rule.md` and `exit 0; cat rule.md` all count as reads: the parser sees a
  reader stage with the rule among its arguments and never asks whether the shell would
  have reached it. (`if false; then cat rule.md; fi` does NOT release — `if`/`then` are
  argv[0] of their own stages, so no reader is found. That is an accident of the split,
  not a decision.) Evaluating this needs a shell, not a parser.
- **Heredoc body lines are scanned as commands.** `python3 - <<'EOF'` … `cat rule.md` …
  `EOF` releases, because the body is split on newlines like any other sequence.
- **A partial display counts as a whole read.** `head -20 rule.md` and `sed -n '1,5p'
  rule.md` release the rule; only a display of literally nothing (`head -0`, `tail -f`,
  `sed -i`, a stdout redirection, a non-reader later in the pipeline) does not.
- **A failed read is only detected in a structured response.** `is_error`, `interrupted`
  and a top-level `exit_code`/`exitCode` in a dict response suppress the observation; a
  plain-string response, or an exit code nested under `metadata`, does not — a failed
  `cat` reported as text still releases the rule.
- **A shell command that merely QUOTES a patch body is treated as authoring those files.** The
  headers count when they start a line and the text contains `*** Begin Patch`, and a heredoc
  carrying a patch as *data* (`python3 - <<'PY' … *** Add File: src/a.ts … PY`) satisfies both.
  Distinguishing the two needs a shell interpreter, not a parser. It bites in one place only:
  working on this hook's own tests and fixtures, where patch bodies are the subject matter.
  Deliberate — the alternative is letting a real `apply_patch <<'PATCH'` through.
- A loop is never an observation (see the parsing bullet above): a model that reads its rules in
  a `for` loop stays held until the valve releases it.
- **A `pi` process spawned from a packed child's shell inherits `PI_HIVE_AGENT`**, so the
  nested session is gated as that agent — carrying its packs and its read-only scoping —
  rather than as a main thread of its own.

## Tests

`python3 global/hooks/rule-delivery/test_rule_delivery.py` — payload fixtures per harness fed to
the script on stdin, asserting on stdout, stderr and the exit code. No harness, no network. The
PI side is covered by `harness/pi` (`npm test`), the deploy side by
`.claude/skills/deploy-global/tests/test_rule_delivery_deploy.py`.

Only a live harness can settle: that Claude/Codex/Grok/PI route these payload shapes to the
deployed hook at all, PostToolUse included; that Grok still clips a denial reason at ~264 visible
characters and whether PI clips at all; whether Codex emits any compaction event; and whether a model, told to read a file,
actually reads it rather than waiting out the valve.
