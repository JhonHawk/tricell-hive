# Evidence research

Use sources that can answer the specific question: official documentation and standards
for supported behavior, inspected implementation or reproducible observations for actual
behavior, and firsthand user reports for experience. User anecdotes do not establish
prevalence or a runtime guarantee.

- Identify the applicable product, version and date before comparing claims. A document
  for a newer version does not settle the installed version's behavior.
- Open the source supporting each consequential claim; search snippets and remembered
  documentation are leads, not verification. Prefer the primary source over a summary.
- Record enough source context to check the claim: URL or local file location, publisher,
  relevant version/date and the passage or behavior supporting it. Cite sources near claims.
- Preserve disagreements when scope, version or direct evidence cannot resolve them.
  Separate a documented capability from a measured outcome and from a recommendation.
- Report supported answers and unresolved parts separately. Missing tools, inaccessible
  sources and unexecuted experiments remain unverified, never negative findings.

Scale the output to the question. A comparison needs the dimensions that affect the
choice; a recommendation needs its supporting evidence and material tradeoff. Neither
requires a formal report, fixed source count or implementation plan.
