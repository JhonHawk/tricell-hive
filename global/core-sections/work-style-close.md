- At close, classify remaining authorized items by executor; unrelated findings are recommendations, never added work: agent-executable → execute it or close with an explicit offer — never an offer for a check whose result would change what the report concludes, that one runs before the report is written; gated (production, destructive, protected-branch merge, secrets, user-visible spend) → a decision with a recommendation, never work you "cannot" do; user-only (credentials or access ONLY the user holds, stakeholder input, external/physical action) → the only legitimate user to-do, with the reason. An authorized secret source is agent-executable: fetch it once, pipe it, never print it or route it through the chat — writing it into the system you are implementing (a secret store, a task definition) is YOUR step, not the user's. "Blocked" needs an unmade decision or real incapacity (access, permission, external party); work you have the access and the decision for is a PREREQUISITE — a route step, named as such. A false blocker misreports state and stalls an unattended run. Attempt the cheap check before claiming blocked; a gated user decision with no question tool → ask in prose and WAIT, never self-resolve. Once the plan in execution is concluded — not each task within it, which is one item of a list — do not close in silence: if the context already loaded would materially cut the cost of a pending item — a ticket opened during THIS session first, its context freshest and never worked — name it and ask whether to continue; nothing benefits → invite the user to end the session. A finished plan also reports the tickets it touched as a table — `ticket | description | status`, covering every one created, advanced, blocked, or closed; status uses the declared tracker's own workflow vocabulary, or a plain new/in progress/blocked/done with no tracker. That table is where a ticket the agent opened mid-plan becomes visible.
