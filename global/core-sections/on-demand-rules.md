## On-Demand Rules
- The routers are `language-rules`, `task-routing` (also fired from the Git section above, at first edit-intent or the first git verb), `workspace-conventions`, `memory-policy` and `unattended-delegation`. Not invoking one is identical to not having its rule. Load it BEFORE acting, never after; being wrong costs one read, skipping costs the rule. "Simple edit", "I know this convention", "I'll check it afterwards", and "too small to route" are rationalizations, not exemptions — size decides delegation, never whether a rule applies. A reference already read this session is not re-read.
- MANDATORY FIRST ACTION for any code task on Codex: invoke the `language-rules` skill and read the references matching the files in play for THIS task — stack rows plus the quality depth rows whose triggers fire — not the repo's whole stack inventory. Review/verification subagents load only their lens's rows; a reference already read this session (and not compacted) is not re-read. opencode gets language rules via its plugin — load the skill only for the quality rows; Claude Code loads only the browser row. Exception shared by Codex, Grok AND opencode: naming identifiers before the file exists (new fields, enums, table/spec properties) has no glob to fire — invoke `language-rules` and read `identifier-language.md` BEFORE choosing the names; the gate above states the rule, that reference carries the judgment.
- At FIRST EDIT-INTENT on a software project (same moment as the git mode), at the first git verb of a session that never reaches edit-intent (a commit-only session), before the FIRST delegation, before choosing which specialist gets a task, and before writing a plan's tasks: invoke `task-routing` — its gap analysis resolves prerequisites (accounts and roles, seed rows, running services) before the code, not at the gate. A read-only investigation, a short question, work outside a software project, and the trivial carve-out never reach either trigger. The core already condenses the specialist table and the delegation/verification budgets below — do NOT re-read those; the skill is for what is not here: multi-agent chains, chain interruption, the NOT-to column that disambiguates a routing row, the plan's gap analysis, and the `git-mechanics.md` reference (branching model, session mode and commits, PRs & promotion, end-of-work hygiene, recovery).
- Before creating/moving/naming ANY file outside application source in a `projects/<group>/<project>/` workspace (or a repo with `_support/` or a `<project>-specs` sibling), before "what's next" with a ledger, before offering `/flow-*`, and before changing a cross-service contract: invoke `workspace-conventions`.
- Before the FIRST Engram memory operation of a session in a multi-repo workspace: invoke `memory-policy`. Floor even if it never loads: one unified Engram project `<group>-<project>` per workspace (`.engram/config.json`; ambiguous → pass `project` explicitly); status facts upsert via deterministic `topic_key`, never append duplicates. Plugin protocol wins on mechanics; mid-session `mem_save` only for facts that would hurt to lose now (decision, root cause, correction) — the rest consolidates at close in ONE pass (upserts plus one summary, updating any mid-session summary). No Engram in session → skip.
- On an explicit unattended handover ("full control tonight", "don't ask until I'm back"): invoke `unattended-delegation` BEFORE declaring the mode accepted. Silence, absence, or a long task never activates it; non-delegated unattended runs fail closed.
- With a project ledger (`_support/PROJECT.md`): never execute a flow command uninvited; never offer a production deploy as an automatic next step.
- An endpoint another service consumes, changed cross-service shapes, or new events/webhooks: define or update the contract BEFORE implementation (`workspace-conventions`); touching multiple repos is not itself a trigger.
- Answer "what's pending / where are we" from ground truth by claim type: implementation → git/disk first (closing commit, file on disk); tool/library behavior → docs for the installed version, never latest. A workflow, script, command, or path named in prose → the artifact itself, starting with whether it exists: prose describes the system as of the day it was written, and a migration falsifies it without editing a line, so N documents agreeing are not N confirmations when all derive from the same superseded state. A negative claim carries the evidence for the negative (the validation that refuses it, the absent file, the date checked). Ledgers, tickets, and memory corroborate, never substitute; on conflict, live state wins. Beyond one quick call, delegate the external reads (tracker, PRs, deploy jobs, remotes) to state-fetcher; reading the local ledger and deciding what is pending stays yours.

Code discovery: `rg` for search and absence claims — including the absence you assert by fixing one occurrence and moving on — then Read. Full routing and the anti-conclusion discipline: the language-rules `code-search` reference — load it before discovery/search work.
