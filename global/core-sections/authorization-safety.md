## Authorization & Safety
- Ask before destructive or hard-to-reverse actions: force-push, history rewrites, production infra changes, restarting or scaling production services, DNS/security groups, data deletion, truncation, destructive migrations. Carve-out: non-prod deploy/restart/scaling with a documented rollback path or under a declared pipeline is standing-authorized — declare it; production always confirms. "Documented" means written down or scripted BEFORE the deploy (blue-green swap, previous artifact/image tag, or a fix-forward path where the change is irreversible) — mentioned in chat does not qualify, and with neither the deployment is not ready, whatever the environment. These gates — plus secrets, direct commits to protected refs, merge or promotion into the production-deploying branch, and CRITICAL/HIGH supply chain with no safe path — never vary by mode or delegation.
- Never write real secrets to durable files. Placeholders, env vars, or secret managers; semi-obfuscated identifiers only in reference docs when identification is necessary. Untracked local secret stores are the sole exception (`_support/secrets/` at the workspace layer; session-scoped copies, both `0600`).
- Reusable cross-project secrets: 1Password CLI (`op`) if installed, else the OS-native keychain — fetch ONCE per session into an untracked session `.env` (`0600`) and read from that copy; the manager's confirmation modal stalls agents, so never query it repeatedly, and an unconfirmable modal in an unattended run is a user-only blocker (queue, don't retry-loop).
- Confirm before system-wide installs (Homebrew, global npm/pnpm/uv tools, system Python, shell profile changes). Local dev servers may start freely for verification; stop what you started before closing and declare it, or ask whether to leave it running when the user is mid-verification — same for browser sessions.
- The security floor is gated on exposure, not project stage: auth, injection/SSRF prevention, and CVE checks apply whenever work touches real user data, production systems, or the public network. Never concatenate user input into SQL or shell — parameterized queries, safe process APIs. Sanitize raw HTML; rely on framework escaping. Exposed new endpoints need auth unless documented as public (marketing, signed webhook, OAuth callback, health probe, public read API).
- Before installing a dependency version, check OSV.dev: compatible fixed version → install it and report the swap (a major-only fix is a bump decision, never silent); MEDIUM/LOW no fix → proceed, report at close; CRITICAL/HIGH no safe path → explicit confirmation, always.
- Never deploy, sync, or copy configuration into a global tool directory unless the user explicitly asks.
