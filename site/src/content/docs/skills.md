Hive's skills supply procedures when a task needs them. The agent selects the
relevant skill; you can also name one in your request. The linked source files
hold the canonical rules.

## Main flows

For where each flow loops and where a requested change returns the work, see the [changes and loops overview](/flows/overview/).

- [Status](/flows/status/): report the backlog and unfinished work, read-only, and recommend what to take next.
- [Research](/flows/research/): investigate an uncertain question and report evidence.
- [Plan](/flows/plan/): settle consequential decisions and define verifiable work.
- [Build](/flows/build/): implement authorized changes and hand over a built candidate.
- [Verify](/flows/verify/): check the candidate at the level you set, then integrate it.
- [Security review](/flows/security/): review a change's security boundaries when you ask.
- [Close](/flows/close/): record the outcome and clean up the work session.
- [Deploy](/flows/deploy/): promote an integrated change and check what is served.

## Supporting skills

- [Shared rules (global guidance)](https://github.com/JhonHawk/tricell-hive/blob/master/content/guidance/global.md): how the agent asks you a decision, handles a change you request mid-work, asks before an effect beyond your machine, and reads the repository's `## Hive` settings; it is always loaded and every flow uses it.
- [Git workflow](https://github.com/JhonHawk/tricell-hive/blob/master/content/skills/git-workflow/SKILL.md): prepare authorized Git delivery while preserving unrelated work.
- [Visual reports](https://github.com/JhonHawk/tricell-hive/blob/master/content/skills/flow-report/SKILL.md): present a report, comparison, or explainer as a designed page.
- [Starlight documentation sites](https://github.com/JhonHawk/tricell-hive/blob/master/content/skills/starlight-docs-site/SKILL.md): scaffold, extend, or audit maintained documentation sites.
- [Harness audit](https://github.com/JhonHawk/tricell-hive/blob/master/content/skills/harness-audit/SKILL.md): audit agent instructions, skills, and role definitions, and the memory each host loads by where a session starts, including host memory and Engram records that restate the rules of Hive or the project, ask the decisions the findings need, and apply what you accept in the current project, including creating or updating a repository's `## Hive` section.
- [Local instructions](https://github.com/JhonHawk/tricell-hive/blob/master/content/skills/local-instructions/SKILL.md): create or prune the project's `HIVE.local.md` and the machine file `~/.config/hive/HIVE.local.md` from what already worked in recent sessions, after asking you which facts to keep.
- [Security advisories](https://github.com/JhonHawk/tricell-hive/blob/master/content/skills/security-advisory/SKILL.md): check whether a published advisory affects your repositories, without changing them.
- [Test audit](https://github.com/JhonHawk/tricell-hive/blob/master/content/skills/test-audit/SKILL.md): trim one area's tests to one owning test per behavior, removing duplicates and tests tied to how the code is written, and prove with a separate review and deliberate code changes that nothing lost its only test.
- [UI criteria](https://github.com/JhonHawk/tricell-hive/blob/master/content/skills/hive-ui-criteria/SKILL.md): find a project's component library, its installed version and its customization layer, keep them in a verified `DESIGN.md`, and give design, build and review work measurable screen criteria that never override the project's own design system.
- [Flow walkthrough](https://github.com/JhonHawk/tricell-hive/blob/master/content/skills/flow-walkthrough/SKILL.md): publish UI captures and their iteration to the [viewer](/viewer/), and walk a built screen for you to validate.
- [Workspace conventions](https://github.com/JhonHawk/tricell-hive/blob/master/content/skills/workspace-conventions/SKILL.md): organize support material, retain useful evidence, and archive closed support sessions you select.
- [Unattended delegation](https://github.com/JhonHawk/tricell-hive/blob/master/content/skills/unattended-delegation/SKILL.md): keep bounded work going after you delegate it, say you are leaving, or go quiet once you have answered the route question and each delivery and review value is answered; feedback within the goal keeps it going, and the delivery questions still missing when you delegate or leave are asked at once without stopping the work, which stops at a verified local result without your answers. When it starts, it also states the amount you gave for unforeseen spend, one sum for a cost no answer covers, or asks for it in one line; without an amount it is zero, and the agent skips that spend and reports it. Within the amount, it takes only an effect it can undo with a command recorded first, and lists each one in the final report.
- [Engram workspace initialization](https://github.com/JhonHawk/tricell-hive/blob/master/content/skills/engram-init-workspace/SKILL.md): establish an explicit workspace memory identity when requested.

For what each coding CLI limits no matter what the skills say, see [Host limits](/host-limits/).
