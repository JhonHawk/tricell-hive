Hive is a small layer of shared instructions, skills and helper roles for coding agents such as Claude Code, Codex and others. It does not replace your agent: the tool keeps its own model, sign-in, permissions and history.

## Install

Run this in a terminal:

```sh
curl -fsSL https://hive.tricell.tech/install.sh | sh
```

Run the same command again later to update. Other install routes, the supported tools and removal are in the [README on GitHub](https://github.com/JhonHawk/tricell-hive#get-started).

## Start with these

- [Research](/flows/research/): answer a question with evidence, without changing anything.
- [Plan](/flows/plan/): settle the decisions of a larger change and split it into tasks you can check.
- [Build](/flows/build/): make an approved change and prove that it works.
- [Close](/flows/close/): wrap up a finished piece of work and tidy what it left behind.

## Getting started

Set it up once, then just ask for what you want.

1. Install Hive with the command above and start a new agent session.
2. Give each repository a `## Hive` section in its `AGENTS.md` with the project name, base branch, tracker and specs folder. The agent asks for a missing value the first time it needs one.
3. Ask for an outcome and say where its limits are, for example:

```text
Investigate why this endpoint times out. Read only; report evidence and options.
Implement the agreed change locally and verify it. Do not commit or publish.
```

## The main flow

From a question to finished work, in order. You can start at any step that fits.

1. [Research](/flows/research/) turns an open question into an answer you can act on.
2. [Plan](/flows/plan/) turns a larger change into decisions, contracts and checkable tasks.
3. [Build](/flows/build/) carries out the change you approved and shows the evidence.
4. [Close](/flows/close/) records where the work ended and cleans up after it.

## Supporting skills

The agent picks these up when the task calls for them.

- [git-workflow](https://github.com/JhonHawk/tricell-hive/blob/master/content/skills/git-workflow/SKILL.md): branches, commits, pull requests and merges, done only when you allowed them.
- [flow-report](https://github.com/JhonHawk/tricell-hive/blob/master/content/skills/flow-report/SKILL.md): a designed HTML report, comparison, explainer or deck.
- [starlight-docs-site](https://github.com/JhonHawk/tricell-hive/blob/master/content/skills/starlight-docs-site/SKILL.md): start, extend or audit a documentation site like this one.
- [harness-audit](https://github.com/JhonHawk/tricell-hive/blob/master/content/skills/harness-audit/SKILL.md): review a project's agent instructions, skills and roles.
- [workspace-conventions](https://github.com/JhonHawk/tricell-hive/blob/master/content/skills/workspace-conventions/SKILL.md): sort support files, keep the evidence worth keeping, and turn findings into lasting guidance.
- [workspace-archive](https://github.com/JhonHawk/tricell-hive/blob/master/content/skills/workspace-archive/SKILL.md): archive finished work sessions you choose.
- [unattended-delegation](https://github.com/JhonHawk/tricell-hive/blob/master/content/skills/unattended-delegation/SKILL.md): let the agent keep working without you, within a goal and a deadline you set.
- [engram-init-workspace](https://github.com/JhonHawk/tricell-hive/blob/master/content/skills/engram-init-workspace/SKILL.md): give a workspace one Engram memory identity, only when you ask for it.

## Specialist roles

For bounded pieces of work, the agent hands off to helper roles with a clear brief: design, building, documentation, quality checks and independent review. Each host runs them with the model and permissions Hive configures for it. The definitions are in [content/agents](https://github.com/JhonHawk/tricell-hive/tree/master/content/agents).
