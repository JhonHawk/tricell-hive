Hive is a small layer of shared instructions, skills and helper roles for coding agents such as Claude Code, Codex and others. It does not replace your agent: the tool keeps its own model, sign-in, permissions and history.

The global core keeps essential boundaries and tells the agent when to read each
canonical procedure. Reporting applies to findings, explanations and messages
with external links or IDs; greetings and short direct answers need no reference
read. Other references are read when their stated conditions apply. A file being
installed, discovered,
supplied to a model and followed are different things. Smaller global text does
not prove smaller total context or improved reliability for any model family.

## Install

On macOS Apple Silicon or Linux (arm64 or amd64), run this in a terminal:

```sh
curl -fsSL https://hive.tricell.tech/install.sh | sh
```

Run the same command again later to update. Other platforms and install routes, and the supported tools, are in the README's [Get started](https://github.com/JhonHawk/tricell-hive#get-started) section; recovery and removal are under [Update, verify, recover, and uninstall](https://github.com/JhonHawk/tricell-hive#update-verify-recover-and-uninstall).

## Start with these

- [Research](/flows/research/): answer a question with evidence, without changing anything.
- [Plan](/flows/plan/): settle the decisions of a larger change and split it into tasks you can check.
- [Build](/flows/build/): make an approved change and hand over a built candidate.
- [Verify](/flows/verify/): check the candidate at a level you can raise or lower, then integrate it.
- [Security](/flows/security/): an independent review of a change's security boundaries, only when you ask.
- [Close](/flows/close/): wrap up a finished piece of work and tidy what it left behind.
- [Deploy](/flows/deploy/): promote an integrated change through your environments and check what is served.

## Getting started

Set it up once, then just ask for what you want.

1. Install Hive with the command above and start a new agent session.
2. Give each repository a `## Hive` section in its `AGENTS.md` with the project name, base branch, tracker and specs folder. The agent asks for a missing value the first time it needs one.
3. Ask for an outcome and say where its limits are, for example:

```text wrap
Investigate why this endpoint times out. Read only; report evidence and options.
Implement the agreed change locally and verify it. Do not commit or publish.
```

## The main flow

From a question to finished work, in order. You can start at any step that fits.

1. [Research](/flows/research/) turns an open question into an answer you can act on.
2. [Plan](/flows/plan/) turns a larger change into decisions, contracts and checkable tasks.
3. [Build](/flows/build/) carries out the change you approved and hands over a built candidate.
4. [Verify](/flows/verify/) checks the candidate and integrates it; [Security](/flows/security/) joins it when you ask.
5. [Close](/flows/close/) records where the work ended and cleans up after it.

[Deploy](/flows/deploy/) is a separate step after integration, when you ask to promote.

## Supporting skills

The agent picks these up when the task calls for them.

- [git-workflow](https://github.com/JhonHawk/tricell-hive/blob/master/content/skills/git-workflow/SKILL.md): branches, worktrees, commits, pull requests and merges, done only when you allowed them.
- [flow-report](https://github.com/JhonHawk/tricell-hive/blob/master/content/skills/flow-report/SKILL.md): a designed HTML report, comparison, explainer or deck.
- [starlight-docs-site](https://github.com/JhonHawk/tricell-hive/blob/master/content/skills/starlight-docs-site/SKILL.md): start, extend or audit a documentation site like this one.
- [harness-audit](https://github.com/JhonHawk/tricell-hive/blob/master/content/skills/harness-audit/SKILL.md): review a project's agent instructions, skills and roles.
- [security-advisory](https://github.com/JhonHawk/tricell-hive/blob/master/content/skills/security-advisory/SKILL.md): find which of your repositories a published advisory or package compromise affects, with the evidence for each one; the fixes stay in each project's own session.
- [flow-walkthrough](https://github.com/JhonHawk/tricell-hive/blob/master/content/skills/flow-walkthrough/SKILL.md): walks a built screen for you to validate, with captures, a video when a flow needs one, and a dark page of the results.
- [workspace-conventions](https://github.com/JhonHawk/tricell-hive/blob/master/content/skills/workspace-conventions/SKILL.md): sort support files, keep the evidence worth keeping, and turn findings into lasting guidance.
- [workspace-archive](https://github.com/JhonHawk/tricell-hive/blob/master/content/skills/workspace-archive/SKILL.md): archive finished work sessions you choose.
- [unattended-delegation](https://github.com/JhonHawk/tricell-hive/blob/master/content/skills/unattended-delegation/SKILL.md): let the agent keep working without you, within a goal and a deadline you set, on the work already running when you say you are leaving, or on the work you already routed and chose the delivery for when you go quiet. A message that only tells it to continue, acknowledges progress or asks how it is going does not end that; anything else hands control back to you. It decides on its own, never does anything irreversible or destructive except spending you authorized in advance within a ceiling, and reports every decision at the end.
- [engram-init-workspace](https://github.com/JhonHawk/tricell-hive/blob/master/content/skills/engram-init-workspace/SKILL.md): give a workspace one Engram memory identity, only when you ask for it.

## Specialist roles

For bounded pieces of work, the agent hands off to helper roles with a clear brief: design, building, documentation, quality checks and independent review. Each host runs them with the model and permissions Hive configures for it. The definitions are in [content/agents](https://github.com/JhonHawk/tricell-hive/tree/master/content/agents).

## Learn more

### Optional OpenCode V2 context loader

At user scope, Hive delivers `hive/context-loader/index.js` and
`hive/context-loader/context-loader.json` inside your OpenCode home, with no `package.json`, outside the auto-discovered `plugins/` directory.
Installation does not activate them or change your OpenCode configuration.

If you explicitly choose activation, add the absolute installed
`<OpenCodeHome>/hive/context-loader` directory path to the native
`plugins` array in your own `opencode.json(c)`, preserving existing entries, and
start a new session. Only `hive-review-plan` and `hive-review-harness` receive their
fixed canonical reference snapshot. Main-thread questions and other roles are not
covered. The manager derives those snapshots from the validated release payload;
the loader reads no reference files or metadata during requests. Updating them
requires manager regeneration and plugin reload. Editing installed Markdown does
not refresh the snapshot; do not activate the repository's editorial JS template.
The loader supplies the snapshot on each request; it does not enforce the
procedure, change models or permissions, or guarantee cancellation if a snapshot
is unavailable.

To deactivate it, remove that entry or use OpenCode's native
`-hive.context-loader` directive, then reload through the native host. Remove the directory path entry before uninstalling Hive
or downgrading to content without the loader; Hive preserves your configuration,
so leaving the entry can produce a missing-plugin error. New offline packages
use manifest version 2 and require their accompanying manager; v1-only managers
cannot verify them. The current manager retains v1-package support. Package
manifest version 2 is independent of the loader's metadata schema 2, which records
role/resource/digest provenance, not cryptographic authentication.

See the [loader contract](https://github.com/JhonHawk/tricell-hive/blob/master/_support/docs/architecture/deployment-manager.md#optional-opencode-context-loader)
for configuration, ownership and verification limits. Source-level checks are
not native runtime proof; the bounded model experiment has not yet run and remains
blocked on verifying safe, exact memory cleanup.
