# hive-review-ux

When your brief gives frames in a design file, or an image of a design, review them as [Judging frames](skill:create-design/references/review.md#judging-frames) sets in place of steps 1 to 3; step 4 sets the report.

1. Drive the browser with the tool your brief assigns, as [Browser tool](skill:hive-core/ui/ui-verification.md#browser-tool) for a web interface, [Device tool](skill:hive-core/ui/ui-verification/device-tool.md) for a native mobile app. Read [UI verification](skill:hive-core/ui/ui-verification.md) for the widths, themes and correction scope. Identify the intended users and task. Review what the change shows and every region its layout affects, including those it displaces, resizes or reflows (the list below a new toolbar), not the whole screen, with the longest real values and with text 30–50% longer. For screen, shell, layout or pattern changes, read the `UI` section of the plan's `design.md` when the brief names one, the design system the project guidance names and the project's `DESIGN.md` as [UI criteria](skill:create-design/references/ui-criteria.md) defines it, distinguishing an absent record from an inaccessible one. Judge the result against the approved sketches, the approved example when the brief carries its image (each difference is a finding, as step 1 of [flow-verify](skill:flow-verify/SKILL.md) defines it), and the decisions recorded under [UI decisions](skill:hive-core/ui/ui-plan.md): the existing screen each region follows, components, variants and sizes, action placement and states. Sign in only with the accounts your brief gives, as [test accounts](skill:hive-core/local/test-accounts.md) sets for a child.

2. Judge the rendered result against the project's UI library, theme and `DESIGN.md`, following the [precedence](skill:create-design/references/ui-criteria.md#precedence) of [UI criteria](skill:create-design/references/ui-criteria.md) for library defaults and recorded decisions; layout integrity, loading, empty and error states, keyboard order, focus and accessible names are always checked, by measurement and interaction. Report each failure the change introduced in a check marked measured in [criteria](skill:create-design/references/criteria.md) as a defect with its priority; do not judge its screen modes. Run the automated audit on each reviewed state as [automated accessibility audit](skill:hive-core/ui/a11y-audit.md) sets. Layout integrity means: a value that does not fit in two lines is truncated with an ellipsis, its full value shown on hover and in its accessible name; short values (dates, badges, button labels) stay on one line; no word breaks mid-word; no horizontal page scroll; no element overlaps another; at a mobile width the layout reflows to one column where the desktop shows columns side by side. The verdict starts as not passed and judges only the defects the change introduced in the reviewed regions: it is passed when the reviewed states show none, of any priority, and stays not passed, with the report saying the review did not run, when no state could be reviewed. Give each finding a priority from P0 to P3 by observable impact, as [Findings](skill:hive-core/close/close-report.md#findings) defines. List separately, with priorities, every defect in those regions the base already shows; that list does not change the verdict.

3. For the human handoff, read [walkthrough](skill:hive-core/ui/walkthrough.md); return evidence to the primary producer rather than publishing it, and record no video. The brief gives the captures of the changed screens and states and how to reach each state step 2 checks, or which cannot be reached. Cover the regions the change alters and the layouts and shared components that contain or reuse them (containers, lists, dialogs): measure and interact with the running view instead of capturing again, and capture only what the brief lacks, in the parent-assigned evidence destination when tools and permissions allow. A state you cannot reach with the brief's means is listed with what blocked it, is not covered, does not fail the verdict, and is not a reason to stop and ask. For a follow-up after a fix, review only the corrected regions and states it names, the layouts that contain them and their loading, empty and error states, against the findings the fix answers, instead of the scope of steps 1 and 2; still run step 2's automated audit and its layout-integrity, keyboard order, focus and accessible-name checks with the longest real values and text 30–50% longer, and answer in one reply. Return capture links, the actual URL, required role, navigation steps and expected versus observed results; disclose unavailable capture access rather than claiming evidence exists.

4. Report the verdict (passed or not passed) and each finding the change introduced with its priority, user impact, location, reproduction and evidence; then the defects the base already shows and the states not covered. Distinguish source-based concerns from observed interaction failures. Do not modify the interface during review.

Stay within the parent’s assigned scope, write ownership, and output destination. Never run `git stash`, `git reset`, `git checkout` or `git restore` of paths, `git clean` or `git switch` in a working tree other agents may be writing, and never `git stash` while another agent works in any worktree of the repository, since the stash list is shared. Unless the brief says your dependency installation is not shared, run no command that installs, prunes or relinks dependencies and add none to a manifest or lockfile; pause only the work that needs one, name it in your report, and continue. Run a test suite that sets up, resets or binds a local service only on the instance the brief assigns; with none assigned, do not run it and report it as not run. Run install, build and test commands in the foreground with a timeout of at most 10 minutes; report a timeout as not completed. Stop any process you started before returning. Return evidence, limitations and needed decisions in one final reply; before it, send at most one message to the parent, for a blocker that needs its decision, and make that the final reply when no independent work remains.
