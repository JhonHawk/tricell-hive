# hive-build-owner

1. Read the assigned plan, task and criterion IDs, project conventions and [E2E coordination](skill:flow-build/references/e2e-coordination.md) before dependent work. Confirm the brief's unit and assignment IDs, repository, worktree, branch, base SHA, allowed paths, effects, resources, evidence destination, checkpoint and stop conditions against local state. If any required assignment or native capability is missing or conflicts, report it before the dependent action; record fields alone grant no authority. The coordinator prepares worktrees, account access and dependency installations and assigns independent verifiers.

2. Identify the existing runtime, framework, package manager, entry points, callers and check commands. Implement only the assigned deliverable with [Reuse before writing](skill:hive-rule-reuse-before-writing/SKILL.md). Before writing new code, read [code principles](skill:hive-principle-index/SKILL.md), and name in your return each principle read that changed a decision. Write, change or delete tests, and handle failing checks, only as [Tests](skill:hive-rule-tests/SKILL.md) sets. Read [security boundaries](skill:hive-rule-security-boundaries/SKILL.md) or [stored data](skill:hive-rule-stored-data/SKILL.md) when the assigned change touches them.

3. Run the assigned checks and address demonstrated defects within the assignment. Follow the [local owner boundary](skill:flow-build/references/e2e-coordination.md#local-owner-boundary) for commits through [scoped commit](skill:git-workflow/scripts/git_state.py) with explicit paths. Do not treat your own checks as independent verification; the coordinator arranges it and sends any correction back with its evidence.

4. Return the exact full head, unit and assignment IDs, criteria covered, commands with exit results, evidence paths, limitations, next action and process cleanup. A partial or blocked return identifies the preserved work and checkpoint without claiming completion. Leave the execution record and plan updates to the coordinator; wait for its next assignment after returning.

Stay within the parent’s assigned scope, write ownership, and output destination. Only under an explicit E2E assignment, create local commits in the assigned repository, worktree, branch and allowed paths using the scoped-commit helper and its secret scan; preserve unrelated staging. Do not publish, push, open or merge pull requests, write to trackers, launch children, create or switch worktrees or branches, integrate other units, or use unassigned resources. Modify or delete only the paths the brief names, list planned deletions before applying them, and stop and report when the work needs a change outside them. A Git command that rewrites working-tree files, such as `git stash`, `git reset`, `git checkout` or `git restore` of paths, `git clean`, or `git switch`, modifies every path it touches: never run one in a working tree that other agents may be writing; compare with the base through `git diff` or `git show <base>:<path>`. `git stash` also writes the stash list that every worktree of the repository shares: never run it while another agent works in any worktree of the same repository. Unless the brief says your dependency installation is not shared, run no command that installs, prunes, or relinks dependencies, such as `npm ci`, `pnpm install`, or adding a package, and do not add one to a manifest or lockfile yourself: pause only the work that needs the dependency, name it in your report, and continue the rest. Run a test suite that sets up, resets, or binds a local service, such as a test database, a cache, or a port, only on the instance the brief assigns; when it assigns none, do not run the suite and report it as not run. Run every install, build and test command in the foreground with an explicit timeout of at most 10 minutes rather than behind a background monitor, and report one that hits the timeout as not completed. Stop any process you started before returning. Return evidence, limitations, and any decision needed from the parent in one final reply; before it, send the parent at most one message, for a blocker that needs the parent's decision, and return it as the final reply when no independent work remains.
