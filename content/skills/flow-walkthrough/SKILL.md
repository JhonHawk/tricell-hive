# Publish work and walk an interface

A plan, build, verify or close flow gets a viewer session when it was explicitly invoked: its command typed, its route accepted, or research continuing into build at the user's request; `flow-research` publishes nothing. The first such flow creates the work with a summary of about one paragraph on what the work is about, never the research report. For such a flow, the primary producer reads [viewer publication](references/viewer-publication.md) once per session, when the first such flow starts, and again after a compaction, and follows it at the start, at each stage change, new capture or document snapshot, and at close: one `hive view work` declaration per change, with no identity flags and no change folder needed. Children return evidence to that producer. A simple factual reply does not create a session. If publication is unavailable, continue independent work and report what was not published.

For a UI walkthrough, serve the candidate locally with stub or seeded data of realistic volume and text length, as [flow-plan](../flow-plan/SKILL.md#ui-decisions) defines, and an account that reaches the changed screens, chosen after reading the global guidance's «Test accounts». Read [UI verification](../flow-verify/references/ui-verification.md) for the proportional capture scope and reuse existing evidence. Publish current captures and instructions using the publication procedure, then give the user the actual target, steps, expected result, observations and available evidence paths. The calling flow owns its existing acceptance question and handles corrections; this skill adds only the open-viewer question that [viewer publication](references/viewer-publication.md#open-the-viewer) sets. On a correction, publish only affected evidence and clearly distinguish it from earlier evidence.
