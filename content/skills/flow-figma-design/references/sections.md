# Canvas sections

Read before the first drawing, at [flow-figma-design](../SKILL.md) step 5, and again before placing a rule card, a reference image or a piece this work defines on the canvas. A section is the design tool's own container for organizing a page, with a name shown on the canvas; it is not a frame and not a group.

## Nothing stays loose

Every node this work creates on a page sits inside a section this work created: each frame, each rule card, each reference image and each component it defines. Before the review of step 5, read the page's top-level nodes and check that the only ones this work created are its sections; move inside its section any other.

## Which sections

Create these sections, each only when it has content, from left to right in this order:

1. **Assets:** the components and other pieces this work defines in the file, the ones its record lists as `candidate:`.
2. **Moodboard:** the reference material the work brings, such as captures of other products or of the screen it replaces.
3. **One section per flow:** a flow is the screens a user goes through to complete one task, in one app. Screens whose app shell differs, such as a mobile app and a web portal, are never the same flow. A work with one screen has one flow section.

When the user asked for a grouping, in the request or in this conversation, that grouping replaces this list; the other rules of this reference still apply. Before the first drawing, tell the user in one line which sections you will create, by name, without asking: a reply corrects them.

## Names

Name each section `NN · <what it holds>`, such as `03 · Check-in flow`: a two-digit number in reading order, a middle dot between spaces, and what it holds in the session language. When the page already has numbered sections, continue their numbering instead of starting at 01.

## Inside a section

- Place a flow's screens in one row, in the order the user meets them, with their tops aligned and the same gap between them, wide enough for a rule card as [rule cards](rule-cards.md) sets.
- Place below a screen, aligned to its left edge, each other frame of that same screen: a state, an alternative example, and its 440 px frame.
- A rule card stays beside its frame, inside that frame's section.
- Resize the section to fit its content with 80 px of padding on every side, again after each frame added, redrawn or removed.

## Where sections go

Place this work's sections in one row, 200 px apart, to the right of the page's existing content, or below it when the row would be wider than three times that content. A section never overlaps another node.

## What this work did not create

Never move into a section, rename or resize a frame, a section or any other node this work did not create. When the request names existing frames as its target and they sit loose on the page, draw as [A request for the design itself](../SKILL.md#a-request-for-the-design-itself) sets, place what this work creates in its own sections, and ask once, as a decision in step 6's round, whether to group those existing frames too.

## Record and removal

Add one `section: <name> · <node>` line per section to the example's record, next to the frames' nodes. When step 7 removes the alternatives not chosen, resize their section, and delete a section this work created only when it is left empty.

## Without sections

When the connection returns an error creating a section, or the tool has none, draw the frames in the same rows and order without one and say so in step 6's message.
