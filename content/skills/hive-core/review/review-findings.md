# Review findings and the round of fixes

Read when a verify's reviews and the user's answer are in. Read it before fixing anything: how to judge a finding and how to run the one round of fixes.

Apply [Review evidence](review-evidence.md) before accepting a code finding as confirmed, then fix in one round the user's corrections, every UI defect the change introduced, and each confirmed blocking finding; never recommend approving a known defect as is. When the delivery does not stop for validation, list in the final report each difference from the approved example that remains after this round. A UI defect that was already there in a region the change's layout affects goes to the user before the push, as a finding in that validation round, with fix now or a ticket recommended as the ticket rule of [scope changes](../plan/scope-changes.md) sets; fix in this round the ones the user picks. When the delivery does not stop for validation, it goes to the close's findings instead, as [flow-close](../close/close-report.md#findings) sets. A blocking finding, P1 or higher on the scale of [flow-close](../close/close-report.md#findings), is one that breaks a criterion, a contract, data, security or the build. Fix only what each finding names, except that a defect is fixed as [defect fix](../build/defect-fix.md) sets, at its cause and with its other instances, even when the finding names only the symptom; report instead of fixing each finding the reviewer marked plausible rather than confirmed, or whose evidence you cannot confirm. Recheck and recapture corrections as [UI verification](../ui/ui-verification.md) sets. Reread a correction of the UX reviewer's finding as [reviewer brief](../delegation/reviewer-brief.md) sets. Cover in your own walk each state the UX reviewer listed as not covered, or report it as not verified in the validation round or, when the delivery does not stop for validation, in the final report. When a fix changed logic or a contract, review once more, limited to the fixes' diff and the callers of what changed; after that review, a blocking finding gets a local fix with its test and an `Unreviewed: <reason>` line in its commit message, or goes to the user when the fix is not local. Non-blocking findings go to the close's findings, never to another round, and the report says that the second review does not cover what the first one missed.
