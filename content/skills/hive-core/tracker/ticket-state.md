# Ticket state

Read before moving, commenting on, searching or finishing a ticket, or writing its time. The tracker writes it names are authorized by the global guidance's «Scope and authorization». This leaf sets when; [trackers](trackers.md) sets how.

- Without `Completion`, a ticket is done when its changes are integrated into the base branch; move it then, to the state the project uses for that, in the tracker [project settings](../plan/project-settings.md) assigns to its key. That merge is the completion point, except that when the delivery is `ready`, or a human reviewer's approval is pending, the open pull request is the completion point, reached at the stop [merge gate](../git/merge-gate.md) sets: the ticket stays in progress, and a later session that finds it merged runs a follow-up close.
- When the repository's `## Hive` declares `Completion`, a later completion point, the ticket moves to the state its tracker's value declares once the deployment verifies that the ref holds its change. When the deployment's functional walk runs, only a ticket whose criteria it observed in that environment moves, and one it did not observe stays, named in the report; when the walk does not run, the ticket moves and the report names it as not walked.
- Before implementing a tracked ticket, move it to the in-progress state, except for an operational task, as «Scope and authorization» sets; do not start one already there unless the user confirms it is yours.
- At the delivery point (the integration, or the `ready` or `hold` stop) write the time of each ticket the work touched, and update it at the close, as [time](trackers/time.md) sets; an operational task writes it only when the user asks.
- The other tracker writes, and that they take no question, are those the global guidance's «Scope and authorization» grants; [trackers](trackers.md), [close hygiene](../close/close-hygiene.md) «Pending work» and [ticket write](../business/business-ticket.md) set how and when.
- With `Other trackers`, every rule that reads, searches, moves or comments a ticket, or writes its business rules, uses all declared trackers: read and search in each, and move, comment and write the rules of each ticket in the tracker that declares its key prefix, the primary one for a key no tracker declares. Create new tickets in the primary tracker unless the user names another tracker or repository. A declared tracker carries the same write authorization as the primary one.
