# Approved example in the plan

Read when planning a screen and the work folder holds a Figma `examples.md`. The folder is the work's folder under `_support/workspace/`, and the file is the `examples.md` that [create-design](../../create-design/SKILL.md) writes, as step 4 of [UI decisions](ui-plan.md) sets.

Only a screen whose status line in that record reads `approved` has an approved example; one still pending approval settles nothing, so draw the sketches as step 4 of [UI decisions](ui-plan.md) sets and say that the examples await the user's choice.

- Each `rule:` line the record marks as approved is a decision of the plan, and each `assumption` line a decision listed as taken, as [questions](../messages/questions.md) «Decide and list» sets: move the record into the plan as the [rule record](../business/business-record.md) sets. Ask each line still `proposed` as a decision before the plan is approved.
- A `scope` line is a decision only when research already settled it, in the conversation or the work's record; then the screens it stopped get the sketches that step sets. A `scope` line that research has not settled sends the work to research first: name it and end with the next-step block toward [hive-mode](../../hive-mode/SKILL.md); while [unattended delegation](../../unattended-delegation/SKILL.md) is active, report it and its stopped screens as unresolved and plan the other screens.
- An approved example is the after sketch of the regions it shows: write its record in the `UI` section instead of drawing those regions again. When the record holds the user's instruction to record a convention, add the task that writes it among the **Decisions** of the app's `DESIGN.md`, as [design record](../../create-design/references/design-record.md) sets; a `record:` line that reads `pending` means that stage left the fields it names unwritten, so add the task that writes them.
