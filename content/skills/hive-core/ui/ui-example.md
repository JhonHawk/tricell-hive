# Approved example in the plan

Read when planning a screen and the work folder holds a Figma `examples.md`. The folder is the work's folder under `_support/workspace/`, and the file is the `examples.md` that [create-design](../../create-design/SKILL.md) writes, as step 4 of [UI decisions](ui-plan.md) sets.

Only a screen whose status line in that record reads `approved` has an approved example; one still pending approval settles nothing, so draw the sketches as step 4 of [UI decisions](ui-plan.md) sets and say that the examples await the user's choice. Each `rule:` line the record marks as approved is a decision of the plan, and each `assumption` line a decision listed as taken, as [questions](../messages/questions.md) «Decide and list» sets: copy the record's `rule:` lines, except the `stated` ones, and the ticket's control lines to the `## Business rules` section of `proposal.md`, which governs them from then on, as the [rule record](../business/business-record.md) sets. Ask each line still `proposed` as a decision before the plan is approved. A `scope` line is not decided in the plan unless research already settled it, in the conversation or the work's record: then it is a decision, and the screens it stopped get the sketches that step sets. One research has not settled sends the work to research first: name it and end with the next-step block toward [hive-mode](../../hive-mode/SKILL.md); while [unattended delegation](../../unattended-delegation/SKILL.md) is active, report it and its stopped screens as unresolved and plan the other screens. An approved example is the after sketch of the regions it shows, so write its record in the `UI` section instead of drawing those regions again, and when the record holds the user's instruction to record a convention, add the task that writes it among the **Decisions** of the app's `DESIGN.md`, as [design record](../../create-design/references/design-record.md) sets; when it holds a `record:` line that reads `pending`, that stage left the fields the line names unwritten, with or without a `## Hive` section in the app's `DESIGN.md`, so add the task that writes the record with them.
