# Automated accessibility audit

Read when reviewing the UX of a UI change. The audit measures; it does not replace the keyboard, focus and interaction checks of the review.

- When `agent-browser` drives the review, run `agent-browser a11y --tags wcag2a,wcag2aa,wcag21a,wcag21aa,wcag22aa,best-practice --json` in that review's session, under the time limit of [Browser tool](ui-verification.md#browser-tool), on each reviewed state at each width and theme the review checks: every changed screen and every state reached by interaction (an open dialog, popover, menu, panel or mobile navigation), since the audit sees only what is rendered. Scope it with `--selector` to the container of the reviewed regions when one holds them all; otherwise audit the page and report only the results inside those regions. Before each run, wait for a selector or text that shows the state is ready (or `--load networkidle` on a page that does not poll or stream), not a fixed delay. When another browser tool drives the review, run the audit there only when it can execute axe-core in the same page; otherwise report the audit as not run. A native or cross-platform mobile app has no automated audit here: report it as not run, and still check focus order and accessible labels on the device.
- A violation with a `wcag*` tag is a defect, with the priority that [Findings](../close/close-report.md#findings) defines from the observed effect on users, not from axe's `impact`. A violation with only `best-practice` and category tags is a P3 finding marked best-practice, not reported as a WCAG failure.
- Treat each `incomplete` result as pending manual review, not as a pass: check it with rendered colors, keyboard or focus as the rule requires, and name those left unchecked. Markup the project's UI library generates by design (focus guards, portal containers, the `aria-controls` of a closed popup) is noted once, not reported as a defect. Count affected elements from `nodeCount` (the JSON lists at most 10 nodes per rule) and record `axeVersion`.
- axe-core finds on average 57% of WCAG issues, by its maintainer's measure: a run with no violations is not evidence of conformance, and the report never claims conformance from it.
- A UI linter the project guidance names and the machine already has also runs on the running URL; install nothing. Its aesthetic or style rules are informational only, since the project's design system governs the look.
