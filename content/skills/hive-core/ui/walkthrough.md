# Publish captures and walk an interface

Read when an interface is captured, or a walkthrough is asked for. It applies when a build or verify captures an interface, when a flow or role publishes captures, and when the user asks for a walkthrough or demo of a built interface, which follows this leaf alone. The close of a work with captures follows [close the viewer](viewer-close.md).

A build or verify flow that was explicitly invoked (its command typed, its route accepted, or research, plan or build continuing into the next flow at the user's request or as a handoff sets), and a walkthrough or demo the user asks for, gets a viewer session at its first UI capture; research and plan publish nothing, and a flow without captures creates no viewer work. The primary producer follows [viewer publication](viewer.md) at that capture; a child never publishes.

For a walkthrough, serve the candidate locally, or install and launch a native app on the assigned device or emulator as [Device tool](ui-verification/device-tool.md) sets, with seeded data of realistic volume and text length (stub data only for a build's first view, as [UI decisions](ui-plan.md) defines) and an account that reaches the changed screens, chosen after reading [test accounts](../local/test-accounts.md). Take the capture scope from [UI verification](ui-verification.md) and reuse existing evidence. Publish the current captures, then give the user the target, steps, expected result, observations and evidence paths. The calling flow owns its existing acceptance question and handles corrections; this reference adds only the open-viewer option that [open the viewer](viewer-open.md) sets. On a correction, capture again only the affected screens under their same titles: the viewer numbers the new iteration and keeps the earlier one.
