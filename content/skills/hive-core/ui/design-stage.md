# Design stage: offer, file and examples

Read when a route ends in a screen to design, when routing a screen to Figma, or choosing how many examples. Also read at steps 1, 3 and 5 of [create-design](../../create-design/SKILL.md).

- **Connection.** Check yourself that the host has a connection that can write to Figma; never ask which tool to use.
- **When to offer the stage.** For a change the user asked for or a ticket they picked, when the connection exists and the project's Figma file is known, end with the next-step block that recommends `create-design`, with going straight to `flow-plan`, or to `flow-build` for a small understood change, as other replies, and name that stage in the scope line, when either holds:
  - what gets built includes a new screen, even when sibling screens fix its composition and the change would otherwise continue into `flow-build`;
  - an existing screen adds, removes or moves a region, the route would end at `flow-plan`, and neither the request nor an existing screen of the project fixes its composition.
- **The file** is known when the user named it in the conversation, the app's `DESIGN.md` declares it in its `**Design file:**` field, or the project's persistent memory records it; a file of another design tool does not count. Name it in the block, put its link in the command's argument, and say that the stage draws its frames in numbered sections on the page that holds the app's screens.
- **In the stage,** use the file the user or the offering block named, otherwise the one `DESIGN.md` declares, as [design record](../../create-design/references/design-record.md) sets, otherwise the one memory records. With none, ask the user for the Figma file once, as an open question in the text, saying that without one the work goes to the plan with text sketches; when they give none, end as step 1 of the stage sets for a missing connection. Confirm once, before the first write, a file that came from `DESIGN.md` or memory and that neither the block nor the user named.
- **When not to mention the stage:** a change that keeps the screen's layout (a button, a copy, a field, a column); a host without the connection; no known Figma file; and while [unattended delegation](../../unattended-delegation/SKILL.md) is active, when the plan settles the UI as [UI decisions](ui-plan.md) sets. The next-step block is the offer: ask no question that offers proposals for a screen.
- **How many examples.** Draw one example per screen, following the screen's siblings and the decisions recorded for the app. Draw two or three examples only for a screen the user names when asking for alternatives, and then name each screen's recommended example when asking the choice.
