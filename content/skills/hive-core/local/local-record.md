# What a `HIVE.local.md` entry records

Read before adding, updating or marking stale a `HIVE.local.md` entry. It covers `~/.config/hive/HIVE.local.md` and a project's or workspace's `HIVE.local.md`. How to write the file is [local write](local-write.md); local scripts are [local script](local-script.md).

- An entry is one line of at most 200 characters, pointer included, that holds a fact and the date it was last verified; a stale mark, and the date and cause an `unverified` entry gains when it fails, do not count toward that length. Record a fact when all three hold: it says what this machine, account or environment has, lacks, uses or needs (a tool, container, port, host alias, script, cloud profile with its region, the account a tool uses and what it serves, or a tool limitation here with its workaround); a later session can run or check it; and this session confirmed it (a command exited 0, its result was observed, or a command was found missing). The line holds no sequence of steps, no account of what happened, and no version unless the project pins one this machine lacks.
- Keep out of these files whatever is not a checkable fact about this machine: a diagnosis, a measurement, whether a host answers right now, an event, a work item's state (worktrees, processes, what its close kept), what the app's `DESIGN.md` holds, and a fact the repository's tracked files state. A fact that holds for every clone, such as a test command or a CI job, stays out too: name it once, in the final report of the work item that verified it, as a candidate for the repository's tracked guidance. An instruction of the user about this machine or project is a decision: save it in persistent memory and keep in the file one line for what it constrains here.
- When the line cannot hold the command with its flags, or reusing the fact takes two or more steps, save that detail in persistent memory under the topic `local/<slug>`, named after the fact's subject and, when the file sits below the folder that holds the project's `.engram/config.json`, starting with that folder's name, so files that share a project never share a topic. Update the topic when it exists, create it otherwise, in the project «Persistent memory» names for a project file and in `hive-machine` for the machine file. End the line with its pointer, such as `→ engram:hive-machine/local/<slug>`; without Engram, write the line alone, since other hosts do not read a host's own memory. When a detail fails, mark its line stale as [local write](local-write.md) sets; before removing a stale line, write in its topic that it failed, with the date and cause, and leave the topic.
- A child reads the files and does not write them: it reports each fact it verified or found stale, and the main thread updates the right file ([child brief](../delegation/child-brief.md#every-child) sets what its brief carries).
