# Stack skills

Read when onboarding a project, or when the caller asks which official skills its stack has or to install them. It installs third-party skills into the current project only, and only those the user approves. It writes the project's `## Skills` section, which HA-IF-19 of [instruction files](instruction-files.md) defines.

1. **Propose.** Run `python3 -I <harness-audit-dir>/scripts/skill_registry.py propose <repository>` ([skill registry](../scripts/skill_registry.py)). It prints each stack the repository's files show, with the file and field that showed it, and the official sources listed in [stack skills table](../assets/stack-skills.json), with the date that table was reviewed. A stack without official skills, such as iOS, gets no proposal. When it prints no stack, stop: the project needs no section for this.
2. **Ask.** Ask which sources to install as one decision, as [questions](../../hive-core/references/questions.md) sets, one option per source plus none, each with what the source covers from its documentation link and the number of skills it holds. Install nothing the answer leaves out.
3. **Check the installer.** The only route is the `skills` package from npm, in project scope. Pick a version published at least 7 days ago and check it with `python3 -I <flow-build-dir>/scripts/check_package.py` ([check package](../../flow-build/scripts/check_package.py)). Stop and ask when the check reports anything. A vendor's own installer, a Claude Code plugin or a user-scope install is out of this procedure: the first two cannot be checked that way, and a user-scope skill loads in every project.
4. **Pin and read.** For each approved source, take its current commit with `git ls-remote https://github.com/<org>/<repo> HEAD`. Read each `SKILL.md` it holds and every script it ships at that commit before installing. A skill that runs commands or reaches the network beyond what its description says is a finding for the user, and is not installed until they answer.
5. **Install.** From the repository root, run `DISABLE_TELEMETRY=1 npx skills@<version> add <org>/<repo>@<full commit> --skill <name> -a universal -a claude-code -y`, one `--skill` per skill the user approved. `universal` writes `.agents/skills/<name>`, which Codex, Cursor, OpenCode, Pi and Antigravity read; `claude-code` adds a link per skill in `.claude/skills`; add `-a grok` when the project uses Grok Build, which reads `.grok/skills`. The command also writes `skills-lock.json` at the root with each skill's commit and hash. Run nothing else from the source.
6. **Write the section.** Add one `## Skills` line per installed skill, in the format of HA-IF-19, with a trigger taken from what the skill's description says it covers, narrowed to the project's folders where the repository shows them, such as `apps/mobile/`. In a declared workspace, also add each line to the workspace's section with the child's prefix.
7. **Check.** Run `skill_registry.py check` on the repository, and on the workspace when there is one, until it exits 0.

To update later, run `npx skills@<checked version> check` from the repository root, then repeat steps 4, 5 and 7 for the sources it names.
