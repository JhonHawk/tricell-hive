# Apply accepted outcomes

Read after the user's answer to the audit's decisions, before the first edit. Apply nothing the answer did not accept.

1. **Apply.** Edit only the current project, with the host's file-editing tool, and only the outcomes the answer accepted: `delete`, `discoverable`, `stale`, `relocate`, `re-anchor`, `soften`, `demote` with its one-line pointer, `fix`, `insert`, and the `## Hive` section with the facts the global guidance's «Project settings» defines. Never apply `propose-global`, never write `CLAUDE.local.md` or, as an audit outcome, `HIVE.local.md`, and never edit another project: report its findings for that project's own session. Leave `keep` and `manual` entries untouched and list the `manual` ones as remaining work.
2. **Memory.** For an accepted memory outcome (HA-HI-08, HA-HI-11), change only entries about the current project, through the path [memory](memory.md#changing-an-accepted-entry) gives for that host. Before editing a memory file, copy it to a dated backup outside the directories the host reads, with the same permissions, and name the backup in the report; a file that holds a secret value gets no backup. Change an Engram record by updating it, and delete one only when the answer named it. Never change a store setting.
3. **Validate.** For each repository whose `## Hive` section you wrote, run `hive doctor --project <repository>`: exit status 0 and no line naming a retired key mean the section is valid; any other status means it is not, so fix it and run again. When `hive` is not on the `PATH`, and for a workspace section, which `hive doctor` does not check, reread the section against «Project settings» and report that the command check did not run.
4. **Deliver.** Commits, pushes and pull requests follow the delivery mode answered in the Ask round, through [flow-build](../../flow-build/SKILL.md) and [git-workflow](../../git-workflow/SKILL.md).
