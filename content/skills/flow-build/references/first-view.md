# First rendered view

Read at the start of a build whose change adds or rearranges a screen, as [flow-build](../SKILL.md) step 4 sets; that step also sets the order of the tasks.

Before asking the first-view question, decide what keeps going while the user reviews: each task that does not need that answer. Launch one as a child only when [delegation](../../hive-rule-delegation/SKILL.md) sends it to one; keep the others in the main thread while the children work. Show the user the screen's first rendered view with the walkthrough as soon as the UI task is done, compared against the plan's sketch, or against the approved example when the work has one; ask the user to accept it or request corrections, with the open-viewer option that [viewer publication](../../hive-rule-viewer-open/SKILL.md) sets, and adjust only the UI before continuing, adding to the approved example's record each correction that departs from it. Apply the first-view exception when [unattended delegation](../../unattended-delegation/SKILL.md) is active. Skip the first rendered view when the UI task is the plan's last task: the walkthrough of `flow-verify` validates it once.
