# The next-step block

Read before you end a report that moves from one flow to the next, or a work item's close that starts another.

- Moving from one flow to the next (research's status report to a ticket's research, research to Figma design, plan or build, Figma design to plan, build or research, plan to build or research, build to verify) is never asked with the question tool, because a card hides the report it closes. End the report with a separate next-step block: a `---` rule, a bold heading such as **▶ Next step: plan (recommended)**, the reason in one line, and the command the user types to start that flow, written once, in the syntax of the host you run in, with a real argument, such as `/flow-plan COM-833`. Offer a flow's command only when the next step needs that flow's procedure: an investigation, a design in Figma, a plan, or a change to the repository's files with its delivery. No flow needs a ticket: when the work has none, the command's argument is a short description of the work or its change folder, never a placeholder, and a ticket is proposed only as [scope changes](../hive-rule-scope-changes/SKILL.md) sets. Add the other replies the user can give, such as keep investigating or what to change, as a short list with a letter each, `A`, `B`…, so the user can answer with the letter alone. Only the user's reply starts the next flow, except stages covered by the explicit [E2E grant](../flow-build/references/e2e-coordination.md) and five continuations in the same turn: research into build, as [report endings](../hive-rule-report-endings/SKILL.md) sets, research into Figma design for a request whose deliverable is the design and research into [create-prd](../create-prd/SKILL.md) for a request whose deliverable is a requirement document, both as [flow-research](../flow-research/SKILL.md) step 0 sets, build into verify, as [flow-build](../flow-build/SKILL.md) step 5 sets, and plan into build when the user asked for it beforehand or unattended delegation is active, as [plan handoff](../flow-plan/references/plan-handoff.md) sets; typing its command loads that skill whole for that flow, and a flow or skill entered by continuation is read whole before its first step. Keep the question tool for decisions inside a flow: scope, design, delivery and review, validation and findings.
- When the block leads from an approved plan to its build in the same session, or starts another work item after a close, add compacting first as one of its replies, never because of an estimated share of the context window, which the model cannot see: the host's compaction command followed, where the host accepts instructions, by what to keep (the change folder, or the whole plan summary for a plan kept in the conversation, the approved criteria and the delivery answers, or the files and decisions the next work reuses). That compaction is not one «during work» of «Persistent memory»: after it, end again with the same block and wait for the reply.
- Command syntax by host, for that block: `/flow-x` in Claude Code, Grok, Cursor and Antigravity; `$flow-x` in Codex; `/skill:flow-x` in Pi; `@flow-x` in OpenCode. Write the commands of several hosts only when you cannot tell which host you run in.
