# Plan handoff

## When to read

Read when returning a ready plan without implementing it. The plan's own format is in [the plan format](plan-format.md). Reading this reference does not invoke the planning workflow.

## Hand off a ready plan

When returning a ready plan without implementing, summarize it in the conversation, because the saved plan holds the detail and the user may not open it: the objective in one or two sentences; the text of each acceptance criterion `AC<n>` and the name of each requirement the change folder adds, modifies or removes, since they are the contract the user approves; the decisions in force with their IDs, and the minor calls taken without asking with their reasons; each task on one line with what it delivers and who executes it; the verification gates; the delivery mode with the first execution scope, the human-validation stop, the agreed endpoint after validation and any excluded promotion; what remains unresolved or unauthorized; and the change folder or canonical plan path. Do not paste the whole plan. End with the build route question, asked by following [questions](../../hive-core/references/questions.md), which is a route decision and not a request for leave to proceed, since a plan does not authorize implementation: start `flow-build` with that path now (or direct execution for a small change), Recommended when nothing blocks it, or stop with the plan ready. Recommend stopping only for a named blocker, such as an open decision, an unmet dependency, or the user's statement not to implement now, and say which; that the user asked for a plan is not a blocker. Never recommend building the plan just made in another session: this is an exception to the fresh-session route of Recommendations in [reporting](../../flow-close/references/reporting.md#recommendations). The `flow-build` option states that it approves the criteria shown, by their IDs, with a gloss of what they cover, such as "approves AC1–AC4 (export, permissions and audit)", because a host may show the card alone. It also gives the plan's estimated size, as [option scope and size](../../hive-core/references/option-scope.md#give-the-estimated-size) sets. A free-text correction to a criterion or requirement does not answer the route question: revise the plan as [plan revision](plan-revision.md) sets, then show the revised criteria and ask the route question again. Leave the saved change folder uncommitted: keep its status on disk while the work runs, and [flow-close](../../flow-close/SKILL.md) versions it once at close. When execution is already explicitly authorized, show the criteria the same way and continue as permitted instead of asking.
