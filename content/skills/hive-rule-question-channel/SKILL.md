# Asking a round

Read before you ask a round of decisions or findings, or an open question about what the user wants.

- Ask a round of decisions or findings through the host's native question tool when it waits for the answer and the host permits it for that question, and through that tool alone when it also gives each option a description field. Write the message as visible text before the card: the context line, the report or explanation the round needs, and the waiting line, which says what you are waiting for and how many decisions you know are still to come. Where each option has a description field, that text never holds the round's decisions or findings written out, meaning a title line with its ID, a `Situation:` line, option lines or an `I recommend` line: the card carries them, and writing them in both places makes the user read the round twice. Where the options have no description field, that text holds the round written out, as [asking in text](../hive-rule-question-text/SKILL.md) sets. Then, with no tool call in between, ask the round through the tool, each decision or finding as one question: in one call when the round fits the tool's limit per call, such as four on Claude Code or three on Codex, otherwise in consecutive calls of up to that limit with no message between them. Use one question tool per pending question: never send the same question through both an asynchronous tool and a waiting tool, or send another card while its answer is pending. A tool's acceptance receipt is not a user answer. Where a permitted waiting tool carries the question, asking that round only in text is the failure, except in the cases [asking in text](../hive-rule-question-text/SKILL.md) lists. A round's first card with no text before it is the failure, and so is a message after the round's last card other than the reply to a card that comes back unanswered, which [unanswered cards](../hive-rule-card-unanswered/SKILL.md) and [asking in text](../hive-rule-question-text/SKILL.md) set: the turn ends with that card or that reply. A plain acceptance typed instead, such as "ok", "dale" or "con los recomendados", applies the starred options of the decisions the user was shown, in a card that opened or in the text; free text still answers, and a decision a reply leaves out, or one the user was not shown, stays open.
- Write the card to stand alone, since it is the only place the user reads the round: each question opens with the stage and ticket and with the decision's or finding's ID and title, and carries the situation with what the user needs to answer, such as the plan path; each option's label is `A - (★) <two to five words>` and its description carries the `If you choose it:` text, or the option's effect in one line when it has no such line, the starred one ending with the reason of the `I recommend` line and, where [decision format](../hive-rule-decision-format/SKILL.md) asks for it, what remains uncertain. When the options are concrete artifacts, such as sketches, formats or code, show each in the option's preview where the tool offers previews (single-choice questions), otherwise in a code block in the message.
- An open question about what the user wants or needs, as [hive-mode](../hive-mode/SKILL.md) asks it, goes in the text, never through the question tool: one per message, with why you ask and an offer to start without the answer, and without IDs, options or the "ok" line. The question tool keeps the choices between options that [decision format](../hive-rule-decision-format/SKILL.md) sets.
