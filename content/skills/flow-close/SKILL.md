# Close a work item and the session

At entry, read `stage.md` in this skill's folder whole: it holds the leaves close-modes, ticket-state, close-hygiene, close-report, business-rules, support-material, so a step that links one of them needs no new read until a compaction, after which read the packet again. If it is missing, read the linked leaves instead; if its last line is not its packet end line, read the rest; if a `## ` heading the end line names is missing, read that leaf; if the output says it was cut, read the linked leaves.

[Close modes](../hive-core/close/close-modes.md) sets which steps run now, which wait and how the close ends. For explicit E2E work, read [coordination](../flow-build/references/e2e-coordination.md) before closing units or cleaning their resources. [Ticket state](../hive-core/tracker/ticket-state.md) defines the completion point and the state of the ticket at it, including the `ready` stop and the follow-up close of a pull request that was merged later. To clean up, prune, reorganize, curate or archive existing docs or support material, or to check or migrate a project's layout, use [project-layout](../project-layout/SKILL.md) instead of these steps.

1. When this work has viewer captures, close it first, as [publication](../hive-core/ui/viewer-close.md) sets, and read it back. Closing it changes only its record: never stop the viewer service or close the viewer the user has open, even when this work started it. This step comes before any cleanup, which removes the inputs a failed close would need. In the same step, when the work has a ticket, document the ticket with the work's evidence, such as its captures, its test output and its pull request, as [trackers](../hive-core/tracker/trackers.md) sets, before step 2 acts on anything; a close of paused or `hold` work keeps its material and publishes none, and an operational task documents its ticket as the global «Scope and authorization» sets. When the viewer is not running, do not start it: keep the inputs its close needs, continue the rest of the close, and name in the report the viewer session left open with where those inputs are.
2. Take the inventory of this work's support material and apply it as [support material](references/support-material.md) sets, within what [close cleanup](../hive-core/close/close-cleanup.md) authorizes, before steps 4–5, without asking: step 5 removes the worktree and checkpoint the inventory reads, so take the checkpoint's `Principles:` line here too.
3. When the work is integrated into the base branch, move its ticket as [ticket state](../hive-core/tracker/ticket-state.md) sets when the repository declares no `Completion`; with or without `Completion`, update its time as that leaf sets.
4. Close the work's business rules as [business rules](../hive-core/business/business-rules.md) sets. When the work is integrated, mark its plan file closed with `python3 -I <flow-plan-dir>/scripts/tasks.py <plan file> status-set Completed` ([tasks](../flow-plan/scripts/tasks.py)); the file stays where it is, as local support material.
5. Clean up the branches and worktrees of each repository the work touched as [close hygiene](../hive-core/close/close-hygiene.md#clean-up) sets, removing only what [close cleanup](../hive-core/close/close-cleanup.md) lists.
6. Write the final report, the only one of the work item: use the row of [close report](../hive-core/close/close-report.md#variants) that fits, with what `git-workflow` step 9 and `flow-deploy` step 8 handed over as its content, and the principles line of `flow-build` step 5, as step 2 took it from the checkpoint when it held one.
7. Write the outcome to persistent memory as the close record, listing each step that waits for an answer, with the account index rows as [test accounts](../hive-core/local/test-accounts.md) sets, the pending-work records as [Pending work](../hive-core/close/close-hygiene.md#pending-work) sets, each candidate's record as [Candidates](../hive-core/close/close-report.md#candidates) sets, and each ticket's time record as [time](../hive-core/tracker/trackers/time.md) sets.
8. End as the **Reply** line below sets.

Reply: ends as the row of [close modes](../hive-core/close/close-modes.md) sets: [the close footer](../hive-core/messages/report-endings.md#the-close-footer) with the waiting line, or the [close report](../hive-core/close/close-report.md#variants) row alone.
