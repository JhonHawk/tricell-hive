# Batch archive

Read on a hygiene request, such as the close footer's **Hygiene** reply, and at a close whose `Specs` is in another repository, as [close hygiene](../../hive-core/close/close-hygiene.md#archive-the-change-folder) sets. A close of work whose `Specs` is in its own repository archives nothing and records the folder for this batch.

## On a hygiene request

1. **List.** List the change folders still under `<Specs>/changes/` on the base, outside `archive/`, and search persistent memory for the `Archive waiting:` records under `archive-pending/`, with an explicit result limit. A folder with a record is pending; each is one pending item, the count the footer and the status report give. Retire each record whose folder is already under `archive/` on the base with `engram delete <id>`, never `--hard`, or from the host's memory without Engram, as [Pending work](../../hive-core/close/close-hygiene.md#pending-work) item 1 does for a `pending/` record. Before that, name in the report each commit, archive or promote action an older record still holds, since this batch no longer applies them, each with the [project-layout](../../project-layout/SKILL.md) command that would apply it. For a folder without a record, name it with the commit that added it and ask, as one decision, whether its work is integrated; under unattended delegation it stays pending. Skip a folder that an open pull request already carries.
2. **Delivery.** When no delivery answer is in force for the repository, ask only the delivery question, as [delivery questions](../../hive-core/git/delivery-ask.md) sets, before the first edit; the batch is a mechanical change and takes no review question. Under `hold`, leave everything pending and say so in the report.
3. **Check.** For each folder, run `python3 -I <flow-plan-dir>/scripts/check_change.py <folder> --archive` ([check](../../flow-plan/scripts/check_change.py)) and fix each coherence line. Ask the folders with unchecked task boxes, each with its count, as one decision whether to archive them anyway; a no, or unattended delegation, leaves that folder pending. Leave pending also each folder whose delta changes a requirement that a folder left pending in steps 1 to 3, an open pull request's included, adds or changes; name each in the report.
4. **Branch.** In the main checkout, create a branch from the base as [git-workflow](../../git-workflow/SKILL.md) sets; under `direct-base`, work on the base.
5. **Archive.** Take the folders in the order each reached the base, the oldest line of `git log --first-parent --diff-filter=A --format=%cI <base> -- <folder>/proposal.md`, which dates the merge that brought it. For each, run `python3 <flow-close-dir>/scripts/apply_deltas.py <folder> --specs <Specs> --detail "<pull request, merge commit>"` ([merge](../scripts/apply_deltas.py)), fix each refusal, name each dropped scenario in the report, then add `--apply`. When two folders change the same requirement, wait for the next UTC minute before the second, since the archive's name carries the minute that orders them.
6. **Deliver.** Commit as [git commit](../../hive-core/git/git-commit.md) sets and deliver as the delivery says: one pull request, or a push to the base under `direct-base`. Once the delivery reaches the base, after the merge or push you perform or at the next hygiene request's step 1, remove from each record the folder it carried, and soft-delete a record left with nothing, as step 1 sets.

## One folder in another repository

At the close, run steps 3 and 5 on that folder in its specs repository: on a new branch from its base, or on the base under `direct-base`, copying in the folder's uncommitted edits from the checkout or worktree that holds them. Once the archive commit holds those edits, `git restore` the folder in that source checkout. Deliver it as that repository's `Delivery` sets, otherwise as the work's delivery mode sets.
