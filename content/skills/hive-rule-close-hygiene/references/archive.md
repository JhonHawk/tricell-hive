# Archive the change folder

Read at [flow-verify](../../flow-verify/SKILL.md) step 5 and [flow-close](../../flow-close/SKILL.md) step 4.

**When.** With `Specs` in the work's repository and a delivery that commits, archive on the work's branch before its first push (the base under `direct-base`), before the local CI evidence that push needs. The close archives, on a new branch from the base, only a folder left unarchived: by unchecked tasks, by an integration without its archive, or under `hold` once delivered. With `Specs` in another repository, the close archives it there, delivered as that repository's `Delivery` sets.

1. Run `python3 <flow-plan-dir>/scripts/check_change.py <folder> --archive` ([check](../../flow-plan/scripts/check_change.py)) and fix each coherence line. For unchecked task boxes, ask as a decision with their count whether to archive anyway: under `interactive` in verify's validation round, at the close in its round. Under `automatic` or `ready` before the push, ask nothing and leave the folder for the close; under unattended delegation, ask nothing and record it as pending. A no leaves it for the close, or pending at the close.
2. At the close, work on a new branch from the base and copy in the folder's uncommitted edits from where they are.
3. Run `python3 <flow-close-dir>/scripts/apply_deltas.py <folder> --specs <Specs> --detail "<detail>"` ([merge](../../flow-close/scripts/apply_deltas.py)), the detail being the branch name before the push or the pull request and merge commit at the close; fix each refusal, name each dropped scenario in the final report, then add `--apply`, which archives it as `<Specs>/changes/archive/YYYY-MM-DD-HHMM-<change-id>/` in UTC.
4. Commit the paths it changed and moved. At the close, `git restore` the folder in the source checkout once the commit holds its edits, and deliver the move with the support items the close commits, as the delivery says.

**After an archive on the work's branch.** Checkpoint lines go to the archived `tasks.md`, whose path the work state names; commit them with the next fix, and the close discards with `git restore` those left after the last push. A later fix to a merged requirement edits the spec and the archived delta together. When the base brings a later archived folder that changes a requirement this delta changes, rename this folder to the current UTC date and time and rewrite that delta to the resolved spec block before the push or the merge.
