# Instruction-file content

Apply these rules after computing the effective set in [hierarchy](hierarchy.md). Judge each rule by its effect in the sessions that load it.

## Admission test (HA-IF-01)

An always-loaded file keeps:

- one sentence on what the project is;
- build, test and verification commands that are not the ecosystem default, named exactly with checkable pass conditions;
- gotchas: what an agent would get wrong reasoning from the code alone;
- upward pointers that sessions cannot reach on their own.

Everything else needs a stated reason to be resident; classify it:

- derivable from the repository (overviews, directory trees, dependency and script lists, framework names that manifests state) → `discoverable`; apply the no-op test: remove the line and name what the agent would do differently, verifying against disk;
- true but situational (multi-step procedures, inventories, environment detail) → `demote` to a document or skill, leaving a one-line pointer that states when to read it;
- a `never X` or `always Y` that cannot name the failure it prevents, or an adjective such as "clean" without a check → `soften` to the criterion it stood for. A prohibition whose failure is nameable stays.

## Content rules

- **HA-IF-03 — Size as cost.** Report files over 200 lines and Codex project chains near `project_doc_max_bytes` as context cost per entry point. Size alone does not predict adherence; the admission test decides what goes.
- **HA-IF-05 — Deterministic enforcement.** A rule a deterministic mechanism (linter, formatter, type checker, test, hook, CI job, branch protection, host permission rule) can enforce belongs there. When one already enforces it, the prose rule is covered: propose `delete`, except a line telling the agent not to duplicate what the mechanism does. When proposing to move a rule into a mechanism, state that its failure message must give the correction (the expected form or the fixing command), because the agent reads that message instead of the prose rule; when an existing mechanism only reports that a check failed, the prose rule is not covered, so propose adding the correction to the message before `delete`. For a repeatable error being fixed, follow [defect fix](../../hive-core/build/defect-fix.md) for layer selection and the work's scoped evidence.
- **HA-IF-08 — One canonical home.** Flag duplicates and paraphrases across files and levels, including a partial restatement that repeats only some of a rule's steps where the rule applies. Ask the caller which version is the rule, one decision per rule quoting each version with its location, then propose `delete` for the rest (subject to HA-IF-13) or `re-anchor` each as a pointer naming the rule and when to read it. A rule's minimal invariant restated whole in an always-loaded file because it must act before its home is read is not a duplicate. Flag contradictory pairs and never recommend keeping both; an intentional override says what it overrides and why. When a project rule contradicts a global layer such as the deployed Hive guidance, ask the caller one decision per conflict, quoting both rules and their effect, with three options: remove the local rule so the global one applies; keep the local rule, stating what it overrides and why; or rewrite the local rule to extend the global one with only the named case where it differs.
- **HA-IF-09 — Stale paths.** Check backtick paths only when the token contains `/` and ends in an extension; skip tokens starting with `@`, `/`, `http` or `~` and tokens containing `://`, `<`, `>`, `*` or spaces (bare root-level names are skipped to avoid false hits; check those by hand when a file names one as a path). Retry unresolved paths by basename: a moved path is rewritten, an absent one is `stale` and deleted.
- **HA-IF-10 — Recover the rationale.** Before `delete`, `demote` or `soften`, read the rule's history (`git log -S "<line>"`, `git blame`) and any ticket it cites. A rule whose reason still holds is not a candidate. When the reason is gone or was never recorded, say which; without version history, mark the rationale unrecoverable and lower the finding's confidence.
- **HA-IF-12 — HTML comments.** Comments in `AGENTS.md` reach the model in every host and cost tokens; Claude Code strips them only from `CLAUDE.md`. Hiding rationale in comments is not free.
- **HA-IF-13 — Coverage for deletion.** Count as coverage only the project's own instruction layers and deterministic mechanisms. Overlap with a personal or machine-wide global layer is reported as cost, not `delete`, because collaborators and CI may run without it, unless the project declares that layer a requirement (for Hive, `Hive guidance: required` in the repository's `## Hive` section, which makes overlap with the Hive layer coverage). This holds even when the repository authors that layer: its deployed copy reaches sessions only after deployment. A distributed skill or agent is the exception only when every install route ships it with that layer and the host loads that layer into its context: a skill read into the parent conversation qualifies, a child agent only when its host or definition passes the global layer to it (Pi agents need `inheritGlobalContext: true`; Claude Code's built-in Explore and Plan agents run without it).
- **HA-IF-14 — Floor.** A file holding only what the admission test keeps is `already lean`. Do not propose cutting its project description, non-default commands, or needed pointers. In [skills and agents](skills-and-agents.md), a skill that satisfies HA-SK-02 and HA-SK-03 is `already lean`, and so is an agent holding only its purpose, boundary, and return contract (HA-AG-01, HA-AG-02, HA-AG-04).
- **HA-IF-15 — Local files.** Read and verify `CLAUDE.local.md` and `HIVE.local.md` like any other file (`CLAUDE.local.md`'s stale claims outrank correct ones because it loads last), report their findings as `info` for their owner and a `HIVE.local.md` fact that holds for every clone as a candidate for `AGENTS.md`, and never propose writing either; the agent that verifies a machine fact records it in `HIVE.local.md` as [local record](../../hive-core/local/local-record.md) sets.
- **HA-IF-16 — Imports.** `@path` imports load at launch and stop after four hops; splitting a file into imports organizes it but does not reduce context. A backticked `` `@path` `` is literal text, not an import.
- **HA-IF-17 — Hive settings.** For each repository entry point, check the `## Hive` section that [project settings](../../hive-core/plan/project-settings.md) defines: a missing section or required field is `medium`; a value repeated elsewhere in the file is `relocate` into the section; a repository that relies on the workspace section for a required value is `medium` under HA-HI-05 for hosts that do not load it; conflicting values across loaded levels are `stale` at the wrong level. A retired key, as that file lists them, is `stale` with the proposal to remove it, since it authorizes nothing. A `Completion` value without the `<state> on <ref> · <state> on <ref>` shape is `stale`, and a later completion point written in prose, such as "Done = on `origin/qa`", is `relocate` into `Completion`. A tracker the instructions name outside the section that is neither `Tracker` nor in `Other trackers` is `relocate` into `Other trackers` with its key prefixes. A rule that requires confirmation before writing to a declared tracker, which the global guidance already authorizes, and a standing grant written in prose (an administrative bypass, a pre-authorized deployment) have no key: list each with `file:line` as a decision for the user, to remove it or keep it as a stated exception, never `stale`. Propose missing values only from evidence in the repository, such as its default branch or existing declarations, and mark the rest as questions for the caller.
- **HA-IF-18 — Cursor pointer.** Cursor CLI loads the Hive layer from the always-applied rule `~/.cursor/rules/hive.mdc` only in workspaces under the home folder, because it reads `.cursor/rules` from the workspace up to the filesystem root. A repository outside the home folder reaches it only through this line in its `AGENTS.md`, near the top and outside `## Hive`:

  ```markdown
  Cursor sessions: unless your loaded instructions contain the line "# Tricell Hive guidance" as a heading of its own, read `~/.cursor/rules/hive.mdc` before any other action and follow it. If that file is missing, say so and continue.
  ```

  Check each repository outside the home folder used with Cursor CLI (the caller says so, or you confirm Cursor sessions there; a `.cursor/` directory alone is a reason to ask). A missing line is `medium`, `high` when the repository declares `Hive guidance: required`; propose the exact line. An existing line is `keep`, not a redundant pointer under HA-HI-07, since its condition keeps hosts that already load the layer from reading it again.
- **HA-IF-19 — Skills registry.** A project lists the third-party skills an agent must read, and when, in a `## Skills` section of its `AGENTS.md`, outside `## Hive` and outside any installer-managed block. The section opens with the line "Before the work a line names, read that skill's SKILL.md whole." Each line is a list item: an observable trigger (a path or a kind of task), then the skill as a backticked path ending in `SKILL.md`, relative to the folder of that `AGENTS.md`:

  ```markdown
  - Before editing files under `apps/mobile/`: `.agents/skills/expo-router/SKILL.md`
  ```

  Check each repository entry point with `python3 -I <audit-harness-dir>/scripts/skill_registry.py check <repository>` ([skill registry](../scripts/skill_registry.py)). Each path it reports missing and each installed skill it reports unlisted is `medium`; a registry inside `## Hive` is `relocate` into its own section; exit 2 names an input it cannot read. Skills Hive installed carry `assets/hive-managed.json` and need no line. A sentence elsewhere that requires a skill ("use the X skill for UI work") is `relocate` into the section, except inside an installer's managed block, whose next run would revert the move: add the registry line beside the block. A declared workspace repeats each child's lines in its own `## Skills`, with the child's path as prefix on the trigger's paths and the skill's path, because Codex, OpenCode, Pi, Grok and Antigravity do not discover skills below the folder where the session starts; that copy is the stated exception to HA-HI-05's "never by copying" and to HA-IF-08, and `check` on the workspace verifies it. A project with no third-party skills needs no section. To propose and install the official skills of the project's stack, follow [stack skills](stack-skills.md).

## Evidence for each finding

Quote the line, name the effective sets it affects, and state the rationale found (HA-IF-10). For `discoverable` and `stale`, cite the file or command output that already states or contradicts it.
