<Aside type="note" title="Esto es gobierno, no producto">
  Esta página describe *cómo* se construye y aprueba la documentación, no una regla de negocio. Vive fuera de la navegación de especificaciones.
</Aside>

Cada capacidad de negocio se define **por rebanada** (slice): una entrega
vertical, pequeña, aprobable y verificable por sí misma. Una rebanada aporta su
contenido y su entrada en el sidebar — nada más.

## Ciclo por rebanada

<Steps>

1. **Discovery de negocio** — flujo normal, excepciones, reglas, estados, alcance negativo.
2. **BRD** — reglas en lenguaje verificable; el _qué_ y el _por qué_, sin diseño técnico.
3. **Gate 1** — Negocio aprueba el BRD. Sin esto no hay spec técnica ni construcción.
4. **Spec técnica + mock** — contratos, modelo técnico y mock navegable si hay UI relevante.
5. **Criterios de aceptación** — cómo se prueba cada regla, antes de construir.
6. **Construcción + QA** — runtime contra el contrato aprobado.
7. **Gate 2** — UAT de Negocio contra el checklist real. Solo aquí se cierra la rebanada.
8. **Publicación** — la versión aprobada queda como fuente histórica.

</Steps>

## Estados publicables

Publicar un documento **no** equivale a aprobarlo: el estado lo dice la rúbrica
de cada página, con evidencia explícita y fechada.

| Estado | Significado | Uso permitido |
| --- | --- | --- |
| `draft` | Definición o revisión en curso | Publicable si se marca claramente como no aprobado |
| `gate1-approved` | BRD aprobado por Negocio | Desarrollo puede construir contra esta base |
| `gate2-approved` | UAT aprobado | Rebanada cerrada, referencia final |
